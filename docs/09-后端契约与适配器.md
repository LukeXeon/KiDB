# 09 · 后端契约与适配器（方案根基）

> 本章定义 KiDB 对"底层 Redis 服务 + 客户端适配器"的全部假设。**这是从旧文档完整继承的一章——
> 它是整套设计的 forcing function**：[01](01-定位架构与TiDB对齐.md) 里每条"与 TiDB 不一样"的机制，
> 都能追溯到本章的某条约束。
> 内核只依赖本章声明的能力；任何满足本契约的 Redis 客户端都可以经适配器接入。
> TiDB 参照：本章之于 KiDB ≈ client-go 之于 TiDB（路由、退避、拓扑刷新三类责任的规格说明书）。

## 9.1 部署形态假设

- **Redis Cluster 纯集群模式**（16384 slot，hash tag 语义遵循 Redis Cluster 规范）；
- 无服务端模块假设：不依赖任何 loadable module；
- 平台放行 `EVAL`/`EVALSHA`；禁用 keyspace `SCAN`（防止全集群遍历被滥用导致集群卡死）。

## 9.2 命令白名单（方案实际使用的子集）

以下命令构成方案的全部服务端能力需求，均为标准 Redis Cluster 基础命令：

| 类别 | 命令 | 用途 |
|---|---|---|
| Hash | `HSET HMSET HGETALL HMGET HGET HEXISTS HDEL HLEN HINCRBY` | 行数据读写、回表、投影、行内 `_ver` |
| ZSet | `ZADD ZREM ZRANGE ZREVRANGE ZRANGEBYSCORE ZRANGEBYLEX ZCARD ZCOUNT ZSCORE ZLEXCOUNT ZREMRANGEBYSCORE` | 索引桶（范围+等值）、exp 登记册、有序遍历 |
| String | `SET SETNX PSETEX GET GETSET INCR DECR INCRBY STRLEN` | 锁、计数器、序列、版本号、唯一预约 |
| Key | `DEL UNLINK EXPIRE PEXPIRE PERSIST TTL PTTL EXISTS TYPE` | 行 TTL、清理、自省 |
| List | `LPUSH RPUSH LPOP RPOP LRANGE LTRIM LLEN` | 异步索引日志 |
| HLL | `PFADD PFCOUNT PFMERGE` | 索引基数统计、COUNT(DISTINCT) |
| Lua | `EVAL EVALSHA SCRIPT(LOAD)` | 写入原子性、谓词下推、分裂步进、锁 |
| 运维（带外工具使用，不进查询路径） | `CLUSTER(SLOTS) INFO DBSIZE SLOWLOG MEMORY(USAGE) TIME` | 诊断、对账、时钟校准 |

**明确不使用的命令**（即使平台/客户端支持）：

| 命令 | 不用原因 |
|---|---|
| `SCAN` `KEYS` `RANDOMKEY` `FLUSHALL` `FLUSHDB` `SORT` | 平台禁用或无界/高危；方案零依赖（§9.5） |
| `SSCAN` `HSCAN` `ZSCAN` | 单 key 有界、技术上可用，但为规避平台对 `*SCAN` 家族连坐封禁的风险，默认不使用（等值桶已 ZSet 化） |
| `MULTI` `EXEC` `WATCH` `UNWATCH` `DISCARD` | 无 key 命令在集群客户端上路由不可靠，事务语义不成立（§9.5 末） |
| `SUBSCRIBE` `PSUBSCRIBE` 系 | 集群模式订阅无法经单连接覆盖全集群事件流；keyspace notification 加速通道默认关闭（[07](07-TTL与过期清扫.md) §7.3） |
| 模块命令（`bf.*` `cf.*` `cms.*` `tdigest.*` `topk.*`、厂商扩展 CAS 系等） | 服务端能力因平台而异，不进核心路径；列为可选增强，需单独验证立项（[14](14-红线局限与检查单.md)） |
| `GEO*` `X*`（Stream）`BIT*` | 方案无需求 |

## 9.3 适配器路由契约（Client 必须满足）

| # | 契约 | 说明 |
|---|---|---|
| R1 | **slot 计算一致性** | 单 key 命令按 Redis Cluster 规范路由：CRC16(hash tag) % 16384，tag = 首个非空 `{...}` 内容。内核 `keycodec` 自带 CRC16-XMODEM 实现（sigurn/crc16 库，多项式参数化）计算 slot/tag 用于寻址，适配器路由行为必须与其一致——由一致性测试套件强制校验 |
| R2 | **所有命令携带 key** | 内核保证发出的每条命令至少带一个 key（无 key 命令在集群客户端上通常被路由到随机/固定节点，语义不可用）；运维类无 key 命令只允许出现在带外工具 |
| R3 | **EVAL 首 key 路由** | `EVAL/EVALSHA` 按 `numkeys` 之后的第一个 key 路由；内核保证 `numkeys≥1`、KEYS[1] 携带目标 slot hash tag、脚本内所有 key 与 KEYS[1] 同 slot |
| R4 | **逻辑 pipeline** | `Pipeline` 接受跨 slot 混合命令，适配器按节点聚合批量发出，按序返回结果；无事务语义 |
| R5 | **MOVED/ASK 处理** | 适配器自动重定向（有限次数）并刷新拓扑；重定向耗尽返回可识别错误供内核重试（§9.6 退避矩阵） |
| R6 | **context 取消与超时** | 每条命令尊重 ctx 取消；连接级读/写超时可配置 |
| R7 | **EVALSHA 回退** | NOSCRIPT 错误时自动回退 EVAL（script 注册器统一处理，[05](05-写入路径.md) §5.7） |

**不要求**适配器提供：跨 slot 多 key 命令拆分（MGET/MSET/DEL 等）——内核的批量点查全部用 pipeline 单 key 命令实现，不依赖任何跨 slot 多 key 语义。这降低了适配器实现门槛。

Store 接口定义见仓库根包 `kidb`（`store.go`）：`Do / Pipeline / Eval / Capabilities / DoReplica` 五个方法即全部契约面。

## 9.4 可选能力（Capabilities 探测，缺失自动降级）

| 能力 | 探测方式 | 缺失时的降级 |
|---|---|---|
| 副本读 `DoReplica`（只读命令路由到 slave / 只读集群） | 启动期能力位声明 | 热 key 防御 L3 关闭，L1/L2/L4 不受影响（[08](08-自治治理与热Key.md)） |
| 热 key 事件流 `HotkeyEvents() <-chan string` | 能力位声明（某些企业客户端内置热 key 检测上报） | L4 触发仅依赖自研 Telemetry 采样 |
| `TIME` 命令 | 命令探测 | 时钟偏移校准关闭，仅依赖监控告警 |
| **EVAL（硬性，非可选）** | 启动期探测：`EVAL "return 1"` 经任意带 tag key 执行 | **拒绝启动**（`ERR_CAPABILITY`）——EVAL 是写入原子性的唯一机制（§9.5 末） |

## 9.5 SCAN 禁令与事务禁令（设计核心决策）

平台禁用 keyspace `SCAN`；叠加的事实是：即使平台放行，集群客户端对无 key 的 `SCAN` 也只能路由到单一节点（甚至随机节点），返回部分数据——**集群级遍历本来就必须由调用方显式扇出**。禁令只是倒逼了正确设计。

方案内所有曾可能依赖 SCAN 语义的点与对策：

| 场景 | 对策 | 章节 |
|---|---|---|
| 等值索引桶成员遍历 | 等值桶为 **ZSet（member=pk，score=0）**：`ZRANGE bucket cursor cursor+511` 分页；存在性 `ZSCORE`；基数 `ZCARD` | [03](03-数据模型与编码.md) §3.3 |
| 无索引谓词全表兜底 | **exp 过期登记册驱动**：分批 ZRANGE 取 pk → pipeline 回表 → 谓词过滤；默认报错，显式开启 | [07](07-TTL与过期清扫.md) §7.4 |
| 维表加载 / 对账抽样 / DDL 回填 | 同走 exp 登记册遍历 | [04](04-查询路径.md) §4.4、[06](06-元数据与Schema演进.md) §6.3 |
| 取消语义 | context 取消贯穿分页游标与 pipeline（R6） | [04](04-查询路径.md) §4.3 |

等值桶 ZSet 化的代价评估：ZADD/ZREM/ZSCORE 与 Set 系同为 O(log N)/O(1) 量级；单 key 体积略增（skiplist 指针），由桶分裂阈值（8MB）自动吸收；功能零损失，顺带获得 `ZRANGEBYLEX` 字典序能力（前缀搜索副本结构可复用）。

**事务立场：EVAL 是唯一原子性机制**——`WATCH` 按 key 路由尚可工作，但 `MULTI/EXEC/DISCARD` 是无 key 命令，集群客户端无法保证其与 `WATCH` 落同一节点，且连接池模式下每次调用可能归还/更换连接，**事务语义不成立**。方案所有原子性依赖单 slot Lua；不提供任何"禁用 EVAL 的降级写路径"——该路径在集群模式下无法做到正确，留着是隐患。

## 9.6 错误分类与退避矩阵（移植 client-go Backoffer 思想）

> TiDB 参照：client-go 的 `Backoffer` 按错误类型决定退避策略与重试上限（region miss / server busy / lock 冲突各有不同）。
> KiDB 对齐：适配器与内核之间约定错误分类，内核按类决策——**不再"一律重试 3 次"**。

| Redis 错误/故障 | 类别 | 责任方 | 策略 |
|---|---|---|---|
| `MOVED` / `ASK` | 重定向 | 适配器 | 自动跟随 + 刷新拓扑，有限次数；耗尽返回 `ERR_REDIRECT_EXHAUSTED`（内核可整体重试，1105） |
| `CLUSTERDOWN` | 集群不可用 | 内核 | 指数退避（初始 50ms，上限 2s），≤5 次；耗尽 `ERR_CLUSTER_UNAVAILABLE`（1105） |
| `LOADING` | 节点加载数据集 | 内核 | 退避重试，上限放宽（节点恢复需秒级）；耗尽同上 |
| `READONLY` | failover 窗口（写打到原从） | 适配器+内核 | 适配器刷新拓扑；内核退避 ≤3 次 |
| `TRYAGAIN` | 临时（如 slot 迁移中） | 内核 | 短退避重试 ≤3 次 |
| `CROSSSLOT` | 内核 bug（key 布局/Lua 越界） | 不重试 | 直接报错 + error 日志 + `contract_violation_total` 指标——契约套件应提前拦截（[12](12-测试方案.md) §12.4） |
| `NOSCRIPT` | EVALSHA 缓存缺失 | script 注册器 | 自动回退 EVAL（R7），计数 `lua_noscript_total` |
| 超时/连接断开 | 传输层 | 内核 | 读：可安全重试；写：靠 `_ver` 幂等重试（[05](05-写入路径.md) §5.6），不区分"是否已生效" |
| `WRONGTYPE` / 语法错误 | 编程错误 | 不重试 | 直接报错（开发期问题，上线前由测试拦截） |

统一出口：所有重试路径携带 ctx，尊重取消与 `scatter_deadline_headroom` 预算；退避参数走全局变量（[10](10-配置与可观测.md) §10.2）。
**实现**：`kidb.ClassifyError` + `kidb.WithRetry`（根包 retry.go）——按类别分派退避/上限，耗尽映射 `ERR_REDIRECT_EXHAUSTED`/`ERR_CLUSTER_UNAVAILABLE`。
