# 12 · 测试方案

| 层 | 占比目标 | 工具 | 覆盖对象 |
|---|---|---|---|
| 单元测试 | 行覆盖 ≥85%，核心状态机 100% 分支 | testify + miniredis/v2 | 谓词翻译、桶路由、编解码、Lua 脚本行为、类型文本往返、keycodec |
| 属性测试（PBT） | 状态机全路径 | rapid | 分裂/合并协议、TTL 语义、写入并发、双实现比对 |

## 12.2 单元测试（miniredis）

miniredis 内存模拟 Redis（支持 Lua、TTL、过期快进 `FastForward`），覆盖：

- 谓词翻译表全组合：每个 SQL 谓词形态 → 断言生成的命令序列与结果（**断言不含任何 `*SCAN`/`KEYS`/`MULTI` 命令**——回归禁 SCAN 纪律）；
- 写入 Lua（直接执行 embed 的 `.lua` 文件内容，"文件即事实"）：INSERT/UPDATE/DELETE 后行、索引桶、字典序副本、exp、rcpt、唯一预约 key 六项一致性断言（每条用例 = 一次状态全量不变式检查）；
- TTL：`FastForward` 跨过期点 → 点查返回空、索引候选被回表拦截、COUNT 精确、预约 key 自愈路径；
- 服务端下推 Lua 与客户端校验路径**同输入结果比对**（两套实现互为参照）；
- exp 登记册遍历：构造部分行过期的数据集，断言遍历结果 == 存活行集合；
- CRC16/slot tag 表：16384 个 stag 全部自洽（`crc16(stag[i])%16384==i`）；与 Redis Cluster 规范样例向量比对（keycodec 包自带测试）；
- Lua 资产加载：头部元数据解析、禁用命令静态校验（含故意混入 `SCAN` 的负例用例）；
- DDL COMMENT payload：`kidb:{...}` JSON 解析、非法 payload 拒绝、非 kidb 前缀 COMMENT 忽略。

## 12.3 属性测试（rapid，核心资产）

模型：Go map 作为"真理模型"，随机操作序列同时打在真实实现与模型上，每步断言一致。

- **P1 分裂/合并协议**：随机 {写入、删除、过期、触发分裂、触发合并、杀死 Controller、恢复} × 任意交错；不变式：任意时刻任意谓词查询结果 == 模型；BucketMap 状态机永不进非法状态；
- **P2 TTL 语义**：随机 _ttl 写入 + 随机时间快进；不变式：查询结果 == 模型未过期行；COUNT == 模型存活数；**exp 登记册内容 == 模型全量行**（登记完备性是全表遍历与 DDL 回填正确性的前提，单独断言）；
- **P3 并发写入**：多 goroutine 随机写同主键/同索引值；不变式：最终行内容、索引内容、回执、唯一预约 key 四者一致；写入幂等（重复应用同写入不产生变化）；
- **P4 双实现比对**：服务端下推 vs 客户端校验，随机谓词输入，结果集必须相同；
- **P6 DDL 作业**：随机 {建索引作业、kill 执行者、续作、并发写入目标表}；不变式：作业完成后索引内容 == 模型推导的索引；任意时刻查询不出错行（回填窗口内新索引不服务读，由可见性标记保证）；
- 种子持久化：失败用例种子入库，CI 永久回归。

## 12.4 适配器一致性测试套件（contract tests）

任何 `kv.Client` 实现接入前必须通过本套件（testcontainers 起 3 主 3 从真实集群）：

| 用例 | 验证契约 |
|---|---|
| 随机 key+tag 组合，断言命令实际落点与内核 CRC16 计算一致 | R1 |
| 全命令路径抓包/拦截断言：无一条无 key 命令 | R2 |
| EVAL 多 key 同 slot 脚本执行成功；跨 slot 脚本返回 CROSSSLOT（内核前置校验应拦截） | R3 |
| 跨 slot 混合 pipeline 结果按序、无串扰 | R4 |
| 测试中触发 `CLUSTER SETSLOT` 迁移，断言重定向自动恢复；注入持续 MOVED 断言返回可识别错误 | R5 |
| ctx 取消/超时：挂起命令在 deadline 内返回 | R6 |
| `SCRIPT FLUSH` 后首个 EVALSHA 自动回退 EVAL，结果正确 | R7 |
| 声明 `ReplicaRead=true` 时只读命令确实落到 slave（断言 slave 节点命令计数） | §9.4 |
| **错误分类注入**：注入 `CLUSTERDOWN`/`LOADING`/`READONLY`/`TRYAGAIN` 响应，断言适配器与内核按 [09](09-后端契约与适配器.md) §9.6 矩阵的类别与上限行为（不重试的绝不重试，退避参数生效） | §9.6 |

参考适配器（go-redis）在 CI 中运行本套件；私有适配器在各自仓库复用同一套件。

## 12.5 集成测试（真实集群 + 参考适配器）

- 端到端：SQL → 结果正确性（对照 SQLite 执行同 SQL）；类型强转负例用例库（MySQL 怪癖如 `'123abc' = 123`、零日期、字符集排序规则）单独建档——**这是嵌入 go-mysql-server 的主要语义风险面**；
- DDL 端到端：CREATE TABLE（COMMENT 载体全字段）→ 写入 → CREATE INDEX 在线回填 → 回填期间并发读写 → 索引可见后查询正确；
- EVAL 路由校验：写入/下推/分裂 Lua 全路径在真实集群执行，验证首 key 路由约定；
- rebalance：触发 slot 迁移，断言迁移窗口仅重定向重试、无错行；
- 扩缩容：增删节点，断言拓扑刷新后查询正确；
- Sweeper 全挂 30 分钟：查询正确性无损，恢复后积压追平；
- 协议兼容门禁：真实 DBeaver 连接串 + go-sql-driver/pymysql/MySQL CLI 握手脚本（[02](02-SQL服务器.md) §2.10 矩阵）；
- 配置：`SET GLOBAL`/`SHOW GLOBAL VARIABLES` 往返一致；并发 SET 的 `_ver` CAS 冲突重试；多实例传播延迟 < 2s；非法值（超 16MB 桶上限、不存在的表白名单、越界 lease）拒绝；会话级 `SET SESSION` 覆盖不落 `cfg:global`。

## 12.6 故障注入清单

| 故障 | 注入方式 | 验收 |
|---|---|---|
| Controller 分裂中途宕机 | kill 进程 | 继任者断点续作，PBT 不变式成立 |
| Controller 续约失败（锁已丢） | toxiproxy 延迟注入使续约超时 | **watchdog 立即停干活**（[08](08-自治治理与热Key.md) §8.5）；无双 owner 并发控制动作 |
| DDL 回填执行者宕机 | kill | 任意实例巡检接管 `_job` 续作，作业最终完成 |
| Sweeper 实例宕机 | kill | slot 区间 60s 内被接管 |
| 单 Redis 节点宕机 | toxiproxy 断连 | 该 slot 查询报错（预期），副本接管后恢复 |
| 网络分区（网关与部分节点） | toxiproxy | 部分查询降级报错，无错行 |
| 时钟偏移 | 容器时钟偏移 ±30s | COUNT 偏差有界并告警；TIME 校准生效 |
| 整批同时过期（100 万行同 TTL） | 数据构造 | 清扫波次平滑，主线程无 >100ms 卡顿 |
| L4 副本刷新失败 | 注入写失败 | 副本过期自动失效，读回退源桶 |
| EVALSHA 缓存丢失 | `SCRIPT FLUSH` | NOSCRIPT 自动回退 EVAL，无错误 |
| 节点 LOADING / 集群 CLUSTERDOWN | mock 适配器错误注入 | 按退避矩阵行为，耗尽返回 1105，无错行 |

## 12.7 性能验收指标（发版门禁）

数据集：1 亿行 / 32 节点；每版必跑，回归阈值 ±10%。

> **内核侧基线（已落地，`exec/bench_test.go`）**：miniredis 单实例 + 本地回环口径——
> 测内核 CPU/分配与命令形状，**非真实集群 P99**。参考值（M1 Max，2000 行表）：
> 主键点查 ~46µs/1 命令；写入行 ~450µs（write_row.lua + 索引维护）；
> 等值/范围/覆盖/全扫 ~113–136ms——单节点把固定 16384 路扇出串行化所致
> （真实集群按节点聚合后 ≈ 512 命令/节点并行）。命令形状不变式由
> `exec/shape_test.go` 钉死（点查=1 命令，其余=16384 固定扇出）。
> 已知优化面：等值查询单轮 ~18MB 分配（命令/回复缓冲池化候选，B 组条件项）。

| 场景 | 目标 |
|---|---|
| 主键点查 P99 | < 4ms |
| 单条件索引查询 LIMIT 20 P99 | < 10ms |
| 复合条件（AND）P99 | < 20ms |
| COUNT(*) P99 | < 50ms |
| DDL 在线回填 | 1 万行/s/实例限速内推进，在线读写 P99 波动 < 2× |
| 热 key（单值 40% 占比，10 万 QPS 读） | L4 自动触发，单节点负载 < 安全线 70% |
| 大 key（桶逼近阈值） | 自动分裂，全程写入 P99 波动 < 2× |
| 批量过期清扫 | 追平速率 > 10 万行/s/实例 |
| 写入吞吐（同步索引） | ≥ 3 万行/s/单实例 |
| 全表遍历（开启白名单，千万行表） | 限流通道内完成，单命令无 >10ms，集群 CPU 无尖峰 |

## 12.8 对账测试（长期运行）

> **实现状态（v6.x 已落地）**：`controller.Reconciler`（选举锁持有者驱动，1s tick；
> 每 tick 每表抽样 slot 数 = `tuning.toml [controller] reconcile_slots_per_tick` 默认 2，
> 每 slot 登记册首页行数 = `reconcile_rows_per_slot` 默认 64）：

- **在线抽样对账**：抽样 slot 的 exp 登记册取样 → 数据侧推导索引成员 → 比对实际桶
  （正向：活行成员必须存在且范围 score 相符——`index_member_missing`/`index_score_mismatch`；
  反向：桶成员行死且回执已清——`index_member_orphan`，TTL 清扫暂态不误报；
  异步/回填中索引跳过合法窗口）。漂移进 `reconcile_drift_total{kind}` + 告警日志。
  **只观测不自动修复**（写路径自愈 + 回表校验是正确性机制；漂移 = 内核 bug 信号）；
- **唯一预约 key 双向巡检**：数据侧推导预约 key → 占有者行活性，占有者死而预约存
  = 自愈路径之外的长期泄漏（`uniq_reservation_residual`）；活行无预约 = 缺失泄漏
  （`uniq_reservation_missing`——CREATE UNIQUE INDEX 回填缺口的观测面，v6.x review 补）；
  登记册取样为随机页（ZCARD + 随机 offset——首页恒取最早到期批次的偏倚已修正）。
- ~~cnt 计数器校准~~：cnt 已于 v6.x 移除（只写不读的 vestigial——COUNT(*) 由 exp 登记册 Σ ZCOUNT 精确承接，校准无对象）；
- 影子流量：内核重大升级时新旧路径双跑比对，差异率 0 才允许全量（未落地）。

## 12.9 CI 门禁

单测 + PBT（≥10⁴ 用例/种子集）→ 适配器一致性套件 → 集成测试 → 性能基准；任一失败阻断发布。miniredis、go-mysql-server、参考适配器依赖升级各触发一次全量回归。（P5 分类器对拍已随 v6.0 单引擎纪律退役——分歧面整体消失，无需钉住。）
