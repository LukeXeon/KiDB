# 14 · 红线、局限与上线检查单

## 14.1 明确不做的优化/功能（红线记录）

以下项评估过但超出"可维护、可测试"红线或与缓存定位冲突，**本方案不做**，如需启用须单独立项论证：

| 项 | 不做原因 |
|---|---|
| 物化视图（CQRS 增量维护） | 正确性论证与状态空间爆炸，测试成本不可控 |
| RESP3 CLIENT TRACKING 近缓存 | 依赖服务端/代理改造，耦合不可控；L1 TTL 失效已满足 |
| 预测式热点复制（时序预测） | 反应式 L4 空窗仅秒级，预测模型引入新故障域 |
| 自动索引推荐/创建 | 慢查询告警 + 人工 DDL 已够，误判代价高 |
| 桶级 Merkle Tree 对账 | 抽样对账已提供可审计性，全量哈希树维护成本高 |
| 跨查询微合批 | 网关 P99 恶化风险，待真实吞吐瓶颈出现再议 |
| SUM/AVG 聚合索引化 | 写放大明显且分组维度须预声明；`GROUP BY + COUNT` 已覆盖高频，全扫兜底可用 |
| 索引 Hint（USE/FORCE INDEX） | 优化器选路够用，Hint 是逃生门非主路（`FULLSCAN` hint 为例外——它是安全阀） |
| WATCH+MULTI 降级写路径 | 集群模式下无 key 命令路由不可靠，事务语义不成立（[09](09-后端契约与适配器.md) §9.5） |
| keyspace notification 加速清扫 | 集群模式订阅无法覆盖全集群，默认关闭（[07](07-TTL与过期清扫.md) §7.3） |
| Redis 模块命令增强（`bf.*`/`topk.*` 等） | 服务端能力因平台而异，不进核心路径；如目标平台确认可用（如布隆过滤器用于回表前预筛），单独立项 |
| **多行/跨 slot 事务** | 缓存定位 + Redis 物理约束；会话恒无事务态（[02](02-SQL服务器.md) §2.1） |
| **TRUNCATE TABLE** | 全表删除代价无界；用 TTL 或 DROP+重建（[02](02-SQL服务器.md) §2.4） |
| **GRANT/REVOKE 权限体系** | 部署边界问题；账号两级（rw/ro）+ 网络隔离（[02](02-SQL服务器.md) §2.9） |
| **自研/第二 SQL 解析器** | 能用库的用库：v6.0 起单引擎纪律，DDL/DML 全量 go-mysql-server（[02](02-SQL服务器.md) §2.3） |
| **fork SQL 引擎/解析器** | fork = 永久背锅上游演进；gms 分析器零规则变更，扩展一律走 COMMENT 载体（[13](13-TiDB复用清单.md) §13.6） |
| **MVCC/2PC/快照读/GC** | 缓存定位无用（[13](13-TiDB复用清单.md) §13.5） |
| 极简 CM-Sketch 点频估计 | 观察项：桶级 ZCARD 已覆盖等值选择率；出现选路误判案例再立项（[04](04-查询路径.md) §4.6） |
| **L1 临时延寿**（空窗期延长近缓存 TTL） | 可用性 vs 陈旧度的语义未定，待真实故障形态实证再议（v7.0 触发四裁决） |
| **全局 inflight 入口闸** | 单查询 bulkhead + deadline 已覆盖主路径；等压测证明需要入口闸（v7.0 触发四裁决） |
| **单桶硬上限紧急通道** | 与空窗上界重叠——上界到位后分裂不会无限停（[08](08-自治治理与热Key.md) §8.5），此件冗余（v7.0 触发四裁决） |
| **本地兜底存储/请求排队** | 定位红线，永不做：缓存不是数据库，故障期降级 = miss 语义，不引入第二事实源（v7.0 触发四裁决） |

**物理下界**（任何方案不可突破）：跨节点 ≥1 RTT；单 slot 写 ~10 万 ops/s（写热点唯解 = 异步散列，已采用）；回表与覆盖索引的存储-延迟权衡只能按字段选边（已支持）；AP 语义下的最终一致窗口（缓存本质）；网关形态新增一跳（形态代价，[11](11-部署与运维.md) §11.2）。

## 14.2 局限与代价（诚实的边界）

| 局限 | 说明 | 缓解 |
|---|---|---|
| **延迟税** | 点查从原生 KV 的 ~0.3ms 升至 ~1ms（scatter+回表+校验）+ 网关一跳 0.2~1ms | 近缓存、覆盖索引、软路由逐层压回；超热路径保留裸 KV 旁路 |
| **SQL 是子集** | 跨 slot 事务、大表 JOIN、TRUNCATE 不支持；`SELECT *` **含** `_ttl` 尾列（gms 无隐藏列机制的诚实取舍，[07](07-TTL与过期清扫.md) §7.1） | 缓存定位下属合理取舍；复杂查询回数据库 |
| **无索引谓词默认报错** | 禁 SCAN 后全表遍历是显式行为（hint/白名单），非静默降级 | 登记册遍历有界有告警；引导建索引 |
| **最终一致窗口（v7.0 规格化）** | 一致性级别 = Redis 级（[01](01-定位架构与TiDB对齐.md) §1.8）：正常路径写 OK 即全客户端可见（零窗口）；**故障路径**（主 pipeline 第二段崩溃）行成索引败 → 该值索引暂查不到 = 缓存 miss 语义，对账补写/补登收敛；异步索引/读副本/L4 副本为文档化秒级窗口 | 回表校验保证查到的必对（任何路径不出错行）；窗口全部指标可观测 |
| **热值/范围桶写入集中窗口** | v7.0 桶按值/索引寻址后，热值读写与新表范围桶集中到一跳，直至分裂触发（秒级自愈） | 分裂升格为生产必需（[03](03-数据模型与编码.md) §3.3）；空窗上界兜底（≤300s，[08](08-自治治理与热Key.md) §8.5） |
| **全员忙后台空窗** | 集群过载时后台角色退让（设计内行为），空窗有界 ≤300s | 空窗上界强制竞选（v7.0 触发四①）；`role_concede_total`/空窗时长指标告警 |
| **唯一约束并发窗口** | 预约成功到写入提交之间约 1 RTT 的交错窗口，双方可能都提交 | 如实声明（[05](05-写入路径.md) §5.3）；强约束场景业务串行化 |
| **DATETIME/TIMESTAMP 秒精度** | 存 Unix 秒；`(p)` 小数秒精度 DDL 显式拒绝（不静默截断） | 需要小数秒的业务用 BIGINT 存毫秒 |
| **标识符白名单** | 表/列/索引名只允许 `[A-Za-z0-9_]`（≤64）——标识符原样进入 key 布局 | 反引号任意字符名在 DDL 即拒绝（[02](02-SQL服务器.md) §2.3） |
| **唯一索引查重上限** | `CREATE UNIQUE INDEX` 存量查重的 distinct 去重集上限 = `l2_max_collect`（默认 1M），超出拒建 | 超规模先清重再建（[06](06-元数据与Schema演进.md) §6.3） |
| **UPDATE 改主键判重窗口** | 撞活行已报 1062；但"判重预读→删旧写新"非原子，并发交错窗口存在 | 与唯一预约窗口同族声明（[05](05-写入路径.md) §5.5） |
| **autocommit=0 拒绝** | 无事务定位下它是数据谎言（用户以为可 ROLLBACK） | 显式 1235（[02](02-SQL服务器.md) §2.1） |
| **写入时钟对齐** | 内核时钟经 SyncClock 对齐 Redis TIME（30s 重同步）——网关/服务端偏斜不再变成活性误判 | TIME 不可用的适配器退化本地钟 + 监控告警 |
| **EVAL 硬依赖** | 平台必须放行 EVAL/EVALSHA | 启动期能力探测拒绝启动；上线检查单首项 |
| **适配器质量即地基** | 路由一致性（R1）、重定向与错误分类（R5/§9.6）做错会击穿内核假设 | 一致性测试套件是全量 CI 门禁（[12](12-测试方案.md) §12.4），任何适配器先过套件再上线 |
| ~~双解析器分歧面~~（v6.0 消除） | v6.0 起单引擎纪律，分析面与执行面同一语法树（gms） | 分歧面整体消失，P5 对拍退役（[12](12-测试方案.md) §12.9） |
| **嵌入引擎的语义边角** | go-mysql-server 与 MySQL 的类型强转/排序规则存在差异用例 | 负例用例库 + PBT 对照 SQLite（[12](12-测试方案.md) §12.5） |
| **建设成本**（仅平台侧承担一次） | 核心代码（内核+状态机+Lua 资产+Sweeper+DDL 作业）+ PBT 密度，2–3 人月起步 | 这是平台的成本，不是使用者的成本；业务方接入只需 DDL + SQL，测试方案即建设清单 |
| **运维心智** | Controller 选举、清扫积压、分裂阈值等概念，需 1–2 人真正懂状态机 | 全部机制故障安全（全挂只会变慢/变浪费，不出错） |
| **复杂度风险** | 状态机写错一个分支产生隐蔽 bug | PBT + 影子流量 + 抽样对账三重防线 |
| **超大表（10 亿行+/表）** | exp 登记册集中后成员数 = 表行数，线性增长 | 自治细分（5 万成员/8MB 纪律线，Controller 自动 n 分片，不设用户申报——[07](07-TTL与过期清扫.md) §7.2 容量账）；范围索引同分倾斜走复合键分裂兜底（[08](08-自治治理与热Key.md) §8.2） |

## 14.3 上线前置检查单

- [ ] **EVAL / EVALSHA 确认放行**（硬依赖，启动期探测之外的运维确认）
