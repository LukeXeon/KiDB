> **状态：✅ 已裁决并落地（阶段 0~6 全部完成，全测试绿）；仅存阶段 7 真实集群性能门禁（待外部环境）。**
> 本文档为设计推导与裁决记录；现行契约以 docs/01~14 为准。
> **总原则（用户裁决，2026-08-16）：v7.0 实施不得为了兼容旧路径放弃破坏性修改与
> 最优设计**——无过渡形态、无兼容层、无新旧双跑（沿 v6.0"当新项目做"纪律）。
> 触发一：用户裁决——一致性目标从"行+索引原子可见"降为 **Redis 级一致性**（缓存语义），
> 换查询路径 16384 穷举扇出的消亡。
> 触发二：用户裁决（2026-08-16 追加）——取消 `ReadWriteOnly` 纯读写手开关节点豁免，
> 所有节点必须参与后台角色竞选；负载高自动转纯读写形态，空闲节点自动接管（§9）。
> 触发三：用户裁决（2026-08-16 追加）——消除所有非泛型数据结构容器的使用，

> 触发四：用户裁决（2026-08-16 追加）——**空窗兜底三件套**一次做完，其余候选全部不动：
> ①空窗上界（内置 300s，退避竞选的兜底闸，§9）；②唯一预约 TTL 自愈（内置 24h PX，
> §4 轮 0）；③补写死信队列（`dlq:idx:{table}:{idx}`，§8）。**不做**（同批裁决）：
> L1 临时延寿（语义未定，待实证）、全局 inflight 上限（bulkhead+deadline 已覆盖主路径）、
> 单桶硬上限紧急通道（与空窗上界重叠冗余）、本地兜底存储/请求排队（定位红线，永不做）。
> 兜底纪律（与配置纪律同构）：每件必须说得出"兜的具体场景 + 已有防线为什么不够"；
> 常数全部内置（零新开关）；全部行为指标可观测。

## §1 目标：一致性级别对齐 Redis

| 维度 | Redis 本体的级别 | v7.0 的 KiDB 承诺 |
|---|---|---|
| 单 key 写后读 | 写成功即对所有客户端可见 | 写入回 OK 后，点查与索引查询对任何客户端可见（正常路径零窗口） |
| 跨 key 原子性 | **无**（multi-key 限同 slot，无跨 slot 事务） | 行 ↔ 其索引项**不要求**原子同见；故障路径允许有界收敛窗口 |
| 副本读 | 异步复制窗口，可能读旧 | L3/L4 副本读同性质窗口（现状不变） |
| 故障表现 | 主切换丢尾部写 = key 丢失 | 行成索引败 = 该值索引查不到 = **缓存 miss 语义** |

两个维度必须分清（v6 把它们捆在一起卖）：

- **精确性（查到的必对）**：回表校验兜底一切索引残留/脏成员。**v7 不放，地位反而上升**——它是放宽可见性窗口的安全网。
- **及时性（写完立即可见）**：正常路径（同步两段 pipeline 全成才回 OK）保持零窗口；**故障路径**（崩溃/网络断在第二段）允许窗口，以 miss 形式呈现，异步补写 + 对账收敛。

这就是"和 Redis 当缓存用一样"的精确定义：Redis 里 `SET` 发出后连接断开，key 可能已写——客户端不知道成没成，重试即可；v7 写入同理，且重试幂等（§4）。

## §2 v6 偏离诊断

```
超配目标：行+索引+登记册 单 slot 原子可见（超出 Redis 级——Redis 跨 key 本无原子性）
  → write_row.lua 必须能同事务碰全部结构
  → 索引桶/登记册绑行 slot（hash tag = 行 slot）
  → 行按 pk CRC16 散布全部 16384 槽 → 桶跟随散布
  → 查询谓词不携带 slot 信息 → 零 SCAN 纪律排除"问 Redis 哪些 slot 有"
  → 穷举：任何索引查询 = 16384 条探测命令（空桶零补页但命令本身省不掉）
  → 扇出税：服务器侧命令放大（16384×QPS）+ 网关侧构造/归一 CPU
```

v6 在其约束下是最优解；约束被裁决改写后，同一结构变成冤枉税。**16384 是 Redis 协议常量（槽空间），穷举是"桶绑行 slot"的推论**——解绑即消亡。

## §3 核心算法：桶按值/索引寻址，与行 slot 解绑

即 TiDB 的索引组织方式（索引 KV 按 `index_id+编码值` 独立寻址，与行 Region 无关）；
v6 为单 slot 原子性背离了它，约束放松后回归。

### 新 key 布局（改动面）

| 结构 | v6 key | v7 key | 说明 |
|---|---|---|---|
| 行 | `d:{table}:{pk}`（tag=pk） | **不变** | 点查路径整体不动 |
| 过期回执 | `rcpt:{table}:{pk}` | **不变**（跟行，写原子性需要） | 内容升级：撤销 member 带版本戳（§4） |
| 等值桶 | `i:{t}:{i}={v}:{stag}#b{n}`（tag=行 slot） | `i:{t}:{i}={vtag}` | **tag = `{encVal}`**——EscapeValue 已保证转义形态不含 `:{}#`（>128 或含结构字符即摘要 `~x..`），tag 安全零新机制；桶按值落槽 |
| 范围桶 | `i:{t}:{i}:{stag}#r{n}` | `i:{t}:{i}:{r子桶号}` | 默认单桶（子桶号 0，固定 tag 落固定槽）；分裂后子桶各占异槽 |
| 字典序副本 | `i:{t}:{i}:{stag}#l{n}` | 同范围桶形态（`l` 系列子桶号） | ZRANGEBYLEX 集中桶 |
| 过期登记册 | `exp:{t}:{stag}[#n]`（16384 册） | `exp:{t}[#n]`（**默认 1 册**，集中） | COUNT(*) = 1 个 ZCOUNT；全表遍历 = 单册分页；细分机制保留（触发条件从"行数"改为"册热/册大"，ROADMAP 自动项延续） |
| 唯一预约 | `u:{t}:{i}={v}` | **不变**（本来就是值寻址——该模式的既有活样本） | |
| BucketMap | `bm:{t}:{i}:{stag}`（16384 分片） | `bm:{t}:{i}`（每索引一文档） | 内容：热值分裂条目（值→子桶数）+ 范围子桶区间表；1s 读缓存照旧 |
| HLL 基数 | `hll:{t}:{i}` | 不变（本来就集中） | |
| L4 副本注册表 | `r4:{encVal}:{slot}` | `r4:{桶key}` | 粒度跟随桶集中化 |

## §4 写入协议 v7：两段写 + 版本戳 member

### 协议形态

```
[唯一索引存在时] 轮 0：SET NX 预约（异 slot，冲突即 1062；占有者=行 key，重试自识别；
  **预约带内置 24h PX——触发四②自愈：Sweeper 空窗期预约无人释放时，时间兜底防
  唯一值复用被 1062 误拒；撞预约失败时 GET 发现已过期 → Lua 内"占有者比对 + 行活性
  复核"后接管重置，从"只靠清扫单通道"升级为"清扫 + 时间自愈"双通道**；**PX 到期
  配套唯一桶复核**（拿到预约后 ZRANGE 桶逐 member 判活——长命行（>24h 未重写）的
  唯一约束不被时间戳破，实现期推演抓获））
主 pipeline（一次发出，全部响应收齐才回 OK）：
  ① 行 slot Lua（write_row v7）：读旧行（值+_ver）→ 写行+回执 → HINCRBY _ver 得 newVer
     —— 收缩为行本地事务，不再碰桶/登记册
  ② 索引命令组（异 slot，按 Lua 返回的 old/new 值与 ver 构造）：
     撤旧 ZREM 桶 旧member / 建新 ZADD 桶 新member
  ③ 登记册 ZADD/ZREM（异 slot 集中册）
```

- 主 pipeline 任何一段失败（重试耗尽）→ **报错**（Redis 命令失败语义），不静默降级；
  客户端重试幂等收敛（见下）。进程崩溃类无人收错误的窗口 → 对账观测 + 清扫收敛。
- 异步索引设施（alog + indexer）保留给**声明为 async 的索引**（写热点既有功能），
  不再是错误路径的暗降级。

### 版本戳 member：并发交错下不漏行的不变式（正确性核心）

两段化后索引命令与行写不再原子，并发交错出现新形态。设两个并发更新同 pk：
`upd1: 值 A→B`、`upd2: 值 B→A`。行 Lua 串行（upd1 先胜、upd2 终态 A），但索引命令
跨节点无顺序保证——若 upd1 的 `ZREM A桶 pk` 延迟到 upd2 的 `ZADD A桶 pk` 之后到达，
**A 桶成员被误撤 = 漏行**（行值是 A，查 A 却查不到）。

解法：**桶 member 携带行版本戳**——`member = pk \x1f ver`（ver = 行 Lua 内 HINCRBY 的
`_ver`，v6 已有此字段，版本序 = 行写序，无需时钟）：

- ZREM 撤的是**精确旧 member**（`pk|oldVer`），ZADD 建**新 member**（`pk|newVer`）——
  不同版本是不同 member，任何延迟/交错都**互不误撤**；
- 收敛论证：最高 ver 写的 ZADD 所建 member，不存在任何能撤它的 ZREM
  （ZREM 只由"读到旧 ver"的写产生，目标 member 恒为旧 ver）→ **不漏方向得证**；
- 残留的旧 ver member 是脏数据（"多"，永不"少"）→ 读侧回表校验滤掉
  （行 _ver/值不符）+ 同 pk 多 member 由现有 seen 去重 + 对账按 ver 清。
- ZADD/ZREM 对精确 member 天然幂等 → 重试安全；INSERT 重试撞自己预约 →
  占有者比对自识别放行。

DELETE/软删除方向对称（失败只留脏不留漏）。覆盖索引 member 编码（msgp 数组）
引入 ver 段，规则实现期定稿。

## §5 读路径：扇出消亡对照

| 查询形态 | v6 命令流 | v7 命令流 |
|---|---|---|
| 点查 `pk=?` | 1 HGETALL | **不变** |
| 等值 `v=?` | 16384 探测 + 命中桶分页 + 回表 | bm 读缓存 → 1（或子桶数 K）桶分页 + 回表 |
| 范围/ORDER BY/LIMIT | 16384 路种子建堆归并 | bm 区间裁剪 → 子桶集 ZRANGEBYSCORE 分页；**单桶常态 = 顺序分页，orderedMerger 堆退役至多子桶场景（路数=子桶数）** |
| `COUNT(*)` | 16384 ZCOUNT | 1 ZCOUNT（细分后 = n） |
| 全表遍历 | 16384 册分页 | 单册分页 |
| AND 多条件 | 低基数候选 + 校验 | 不变（HLL 基数估算仍是选路输入） |
| 前缀 LIKE | 16384 lex 桶 | 集中 lex 桶 ZRANGEBYLEX |

回表校验、PTTL 消费纪律、`_ver` 活性哨兵、死行滤除——全部照旧（与桶定位无关）。

## §6 分裂/合并/L4 语义迁移

- **等值热值**：桶集中后热值读写集中到一跳——分裂机制从"优化"升格为"生产能力门槛"。
  分裂 = 值桶 → K 子桶（tag 编入子桶号摊异槽）；写按 `xxhash(pk) % K` 确定性选子桶
  （ZREM 同函数可寻）；读问全部 K 子桶。在线协议照旧（双写窗口 → bm CAS 切读 → 收旧桶），
  member 含 ver 使双写/并集读天然去重。
- **范围/lex**：现有 RangeBucket `[lo,hi)` 区间分裂协议原样复用，仅子桶落槽语义变
  （子桶号 tag 替代行 slot tag）。
- **L4 副本**：ReplicaKey 改替换集中桶 tag 为副本 tag（异槽摊开读），1s 刷新/冷却回收/
  EXISTS 回退全部照旧。
- **Telemetry**：候选登记粒度从 (值, slot) 变 (值)/(索引, 区间)，框架不变。

## §7 登记册集中：COUNT(*)、全扫、DROP 的连带

- COUNT(*) 精确性**不依赖 slot 绑定**（Σ ZCOUNT 语义不变，册数 16384→1）——精确承诺保留。
- 全表遍历 = 集中册分页（有界批照旧）。
- **登记漏登窗口**（第二段故障）：行靠自身 Redis TTL 物理兜底消失；无 TTL 行的孤儿
  残留由 DROP 作业的新驱动源覆盖：**DROP 收集 = 登记册 ∪ 全部索引桶成员并集**
  （v7 桶是集中全量，比 v6 只靠登记册更强）。
- Sweeper：集中册 ZRANGEBYSCORE 到期 → 回执（行 slot）→ 行 slot Lua 清行/回执 →
  按回执清单**异 slot** ZREM 桶 member（精确版本戳）+ 预约释放（v6 已是异 slot  precedent）。
  框架不变，多一跳异 slot 清理。

## §8 对账/DDL 跟随

- Reconciler 四方向（成员/score/孤儿/预约残留）语义不变，数据源从"16384 分片抽样"
  变"集中桶抽样"；新增方向：**member.ver ≠ 行._ver 的版本漂移**（脏 member 清理依据）。
- **补写死信队列（触发四③）**：indexer 补写重试仍失败（桶被 DROP、日志畸形）→
  条目移入 `dlq:idx:{table}:{idx}` List + `index_dlq_total` 指标，不再死循环/丢弃——
  "补写失败怎么办"的最后一块落点；对账观测扩一项（DLQ 深度）。
- 建索引回填：全扫（集中册）→ 按行值 ZADD 集中桶——不再按 slot 分 16384 组，更简单；
  唯一回填三件套（查重拒建/预约回填/冲突中止）不变。
- DDL 撞名防护、标识符白名单、fsp 拒绝等全部不动。

## §9 角色负载自适应：ReadWriteOnly 开关取消（触发二）

**目标（用户裁决原话语义）**：取消 `ReadWriteOnly` 手动豁免——所有节点必须参与后台
角色（Controller/Sweeper/Indexer）竞选；负载高的节点自动转变为纯读写服务形态，
后台工作自动流向空闲节点。机制选型 = **忙闲退避式竞选**（连续谱，无阈值开关）：

- **忙闲信号**：网关 inflight 请求计数（请求边界原子增减，零成本自包含——
  KiDB 是 IO 密集，inflight 即"本节点正承载多少客户端工作"的直读）；
- **竞选退避**：抢锁（`lk:ctrl` / `lk:sweep:{区间}` / indexer 分工锁）前按自身
  inflight 比例退避——越忙退避越久，空闲节点自然先拿锁。**不设忙/闲二元阈值**
  （无新开关，纪律：新开关默认答案是否）；
- **任职退让**：watchdog 续约与区间循环复查忙闲——忙则主动卸任（release + 短暂
  冷却后继续竞选，仍带退避）。已持区间扫完当前批即不再续抢，自然让出；
- **全员忙** = 集群过载 → 后台角色退让是**设计内行为**：分裂/L4/异步补写
  暂停属性能与可见性收敛功能，正确性不依赖（回表校验滤脏 + 行物理 TTL 兜底）；
  空窗与退避经指标可观测。
- **空窗上界（触发四①，退让的唯一无界点的兜底闸）**：锁持续无人接管超过内置
  上界（300s，不设开关）→ 所有节点**无视退避直接竞选**。兜住"全员持续忙 →
  自治死透 + 热桶越忙越不分裂、越不分裂越忙的正反馈膨胀"。实现 = elector
  一处判断 + 空窗时长指标（注册即接线）。空窗语义从"无界"收紧为**有界（≤300s）**；

**承接原豁免场景（诚实声明）**：`ReadWriteOnly` 原服务的"低资源实例 / 边缘只读
代理"豁免不再存在——裁决"必须参与"优先。退避机制使低流量节点自然多承担后台
（方向符合预期）；跨 WAN 边缘节点可能抢到 Controller 锁——接受（其对 Redis 的
访问链路与读写同源，额外负担为 tick 级控制操作，有限）。

**指标**：`role_concede_total{reason=busy}`（卸任/退让计数）、竞选退避时长观测——
"注册即接线"纪律。

**与主线协同**：§4 的故障路径兜底（indexer 补写）由自适应保证落在闲节点；全员忙时
兜底暂停 = 可见性窗口拉长（可观测），读路径正确性不受影响。

## §10 非泛型容器消除（触发三）

**全仓审计（2026-08-16 实证扫描）**：

| 类别 | 现状 | 处置 |
|---|---|---|
| 裸 `container/heap`（interface{} 驱动） | **零**——业务侧已全部走 `utils.PriorityQueue` 泛型封装（exec/topk、exec/prefix） | 维持；跟踪官方泛型堆提案 `container/heap/v2`（[go#77397](https://github.com/golang/go/issues/77397)，2026-02 活跃），stdlib 落地后退役自研 |
| 预泛型 sort API | 6 处：`sort.SliceStable`×4（engine/translate.go）、`sort.Strings`×2（script/registry.go、exec/exec.go） | → `slices.SortStableFunc` / `slices.Sort`（stdlib 泛型排序，零依赖） |
| 手搓集合 `map[string]struct{}` | 24 处 / 9 文件（exec、bucketmap、reconcile 各 6，translate、ddlconvert、l4 各 2，txguard、registry、ddlexec 各 1） | → `utils.Set[K comparable]`（type 别名 + Add/Has/Delete/Items，~20 行自研）：集合语义类型化，零依赖零开销 |
| `container/list` / `container/ring` / `sync.Map` / `[]interface{}` 容器 | **零使用** | 无需行动 |

**库选型裁决（网络调研，2026-08）：零新依赖。**

- **不引** [deckarep/golang-set/v2](https://pkg.go.dev/github.com/deckarep/golang-set/v2)：
  24 处全是函数局部临时去重集合，用不上 Union/Intersect 代数；其默认 `NewSet`
  带锁（线程安全形态）有额外开销。**记名候补**：OR 谓词 pk 集合代数落地时
  （v6.0 审计已记名）再行评估。
- **不引** [emirpasic/gods](https://github.com/emirpasic/gods)：主仓至今未泛型化
  （[issue #245](https://github.com/emirpasic/gods/issues/245)），泛型仅存在于 fork。
- **不引** [PCfVW/d-Heap](https://github.com/PCfVW/d-Heap-priority-queue)（d-ary 堆，
  decrease-key/O(1) lookup）：特性超出需求（归并堆只需 Push/Pop/Len），自研已测。
- **不引** [hashicorp/golang-lru/v2](https://pkg.go.dev/github.com/hashicorp/golang-lru/v2)、
  [tidwall/btree](https://github.com/tidwall/btree)：无对应使用点
  （缓存 = otter/v2 泛型库已在用；有序性由 Redis ZSet 承担，进程内无需有序映射）。
- 纪律延续：依赖即负债；stdlib 优先 → 自研微件兜底 → 库仅在有真实消费方时引入
  （v6.0 泛型审计同款推荐序）。

**净效果**：消除全部 6 处预泛型 API + 24 处手搓集合类型化，新增代码件仅
`utils.Set[K]`（~20 行），**新增第三方依赖 = 0**。

## §11 代价与风险（诚实清单）

1. **热值集中**：v6 散布天然抗热；v7 单值单桶，热值写集中到一跳直到分裂触发
   （秒级自愈窗口）。低基数字段（gender 两值）常态集中，依赖分裂可靠——**分裂从
   优化项升格为生产必需**。
2. **单桶物理上限**：ZSet 单桶百万级成员内分页无碍；超大靠分裂兜底。范围桶默认
   单桶 = 新表写集中 1 槽直至分裂（预分裂列为开放问题 §12）。
3. **写入命令数上升**：1 Lua → 轮0（仅唯一约束时）+ 1 Lua + (2×索引数+1) 条异 slot
   命令同 pipeline。常数级，可忽略；但单 slot 原子性让渡为"正常路径零窗口 +
   故障路径有界收敛"。
4. **脏 member 内存占用**：并发交错残留率 = 交错率 × 延迟率（低），对账周期内清理。
5. **member 变长**（版本戳数字节）+ 覆盖 member 编码改版。
6. **对账告警语义**：故障窗口期漂移指标升高是设计内行为，告警阈值需区分
  "窗口期漂移"与"持续漂移"（后者才是 bug 信号）。
7. **角色自适应（§9）**：低资源/边缘豁免场景消失（裁决覆盖）；全员忙时后台
  空窗（有界 ≤300s，触发四①上界兜底）= 自治功能暂停（性能功能让路读写，
  正确性不受影响）；退避函数参数为内置常数，不同规格混部集群的均衡粒度需实证校准。

## §12 开放问题（裁决时定）

- 范围/等值桶是否支持建索引时**预分裂**（DDL 期声明 K 子桶）——默认答案：否
  （自动分裂承接，纪律：新开关默认答案是否），实证压测触发再议。
- 登记册细分（`#n`）的自动触发阈值——延续 ROADMAP"规模红线触发"自动项，不预置。
- member 版本戳对覆盖索引编码的具体段落位置（实现期定稿）。
- 退避函数的曲线形态（线性/分档）与缩放常数——内置常数起步，压测校准（§9）。
