# 03 · 数据模型与编码

> **TiDB 参照**：TiDB 行 = `t{tableID}_r{handle}` 一个 KV，索引 = 每条目一个扁平 KV key，范围查询 = 有序迭代
> → Redis 无有序 keyspace 迭代（SCAN 亦被禁），唯一的有序结构是 per-key ZSet → 索引段译成 **ZSet 桶**；
> 行译成 Redis Hash 平铺（TiKV 没有的能力红利：投影查询 `HMGET` 免整行解码）；
> 唯一索引 key 模型原样保留（每值一 key，value=行 key），见 [05](05-写入路径.md) §5.3。
> key 布局的唯一所有者是 `keycodec` 包（对齐 TiDB `tablecodec` 纪律，[13](13-TiDB复用清单.md) §13.4）：
> 全仓库任何组件不得手工拼接 key 字符串，一律经 keycodec 构造函数生成——布局演进、转义规则、
> 一致性测试都有单一落点。

## 3.1 Key 规范（`{}` 为 hash tag）

| 用途 | Key 格式 | 类型 | TTL | 备注 |
|---|---|---|---|---|
| 行数据 | `d:{table}:{pk}` | Hash（字段 + `_ver` 版本号） | 用户指定 `_ttl`，无则不过期 | keycodec.`RowKey` |
| 过期登记册 | `exp:{table}:{stag}[#{n}]` | ZSet：member=pk，score=到期时间戳（无 TTL=+inf） | 无 | 兼任全表遍历的官方索引（[07](07-TTL与过期清扫.md) §7.4）；大表按 pk 散列细分 n 分片防超大（§7.2 容量账） |
| 过期回执 | `rcpt:{table}:{pk}` | Hash：{索引id: "桶key member score"} | 行TTL+300s，清扫后删 | |
| 等值索引桶 | `i:{table}:{idx}={value}:{stag}#b{n}` | **ZSet：member=pk，score=0** | 无 | Set→ZSet（禁 SCAN 对策，[09](09-后端契约与适配器.md) §9.5） |
| 范围索引桶 | `i:{table}:{idx}:{stag}#r{n}` | ZSet：member=pk，score=字段值 | 无 | |
| 字典序副本（前缀搜索用） | `i:{table}:{idx}:{stag}#l{n}` | ZSet：member=值+pk 编码，score=0 | 无 | `ZRANGEBYLEX` |
| 热桶读副本 | 源桶 key 的 stag 步进替换 | ZSet + `@ver` 版本戳 | 60s 滚动续期 | 副本 tag = `SlotTag((源slot + k×1820) % 16384)`（stride=⌊16384/9⌋，k∈[1,8]），确定性异 slot 可寻址（[08](08-自治治理与热Key.md) §8.4） |
| 唯一预约 key | `u:{table}:{idx}={encVal}` | String：占有者行key\|ts | 无 TTL（随回执释放，自愈兜底） | 按值散列路由（同值必同 key 同 slot），[05](05-写入路径.md) §5.3 |
| 行计数器 | `cnt:{table}:{stag}` | String | 无 | |
| 异步索引日志 | `log:idx:{table}:{idx}:{stag}` | List | 无 | |
| BucketMap | `bm:{table}:{idx}` | Hash（msgp 编码 + version 字段） | 无 | **稀疏存储**：只存非默认状态的桶（SPLITTING/DRAINING/子桶布局）；默认 ACTIVE 单桶路由由规则推导，不落盘——高基数等值索引（每值一桶）下 bm 字段数不随 distinct 值数膨胀 |
| Catalog | `c:table:{table}` | Hash（schema/索引定义/TTL 默认 + `_ver`） | 无 | [06](06-元数据与Schema演进.md) |
| 全局 schema 版本 | `ver:schema` | String（INCR） | 无 | 任何 DDL +1；plan cache 与 lease 的失效锚点（[06](06-元数据与Schema演进.md) §6.2） |
| 全局配置 | `cfg:global` | Hash（变量名→msgp 值 + `_ver` + `_audit`） | 无 | 内置系统表，[10](10-配置与可观测.md) §10.2 |
| 行版本计数器 | `ver:{table}` | String（INCR） | 无 | 分片化见 [08](08-自治治理与热Key.md) §8.6 |
| 自增序列 | `seq:{table}` | String（INCR） | 无 | |
| 桶统计 | `st:{桶key}` | Hash（ops/估算基数） | 短期 TTL 滚动 | |
| 索引基数 HLL | `hll:{table}:{idx}:{stag}` | HLL | 无 | |
| 控制锁 | `lk:ctrl`、`lk:sweep:{slot区间}` | String（token + PX） | PX 自动过期 | `SET token NX PX` |

> 记号说明：`{table}` 是表名占位（裸插值，非 tag）；`{pk}`/`{stag}` 是字面大括号包裹的 hash tag。
> `{stag}` 是"预计算的 slot tag 字符串"而非数字字面量（见 §3.2）。

## 3.2 Hash tag 机制与 slot tag 表（实施关键）

**目标**：行与其索引桶、回执、登记册、计数器落在同一 slot，使写入/分裂/清扫可以在单 slot Lua 内原子完成。

机制（依赖契约 R1：适配器路由与内核 slot 计算一致，[09](09-后端契约与适配器.md) §9.3）：

1. 行 key 的 tag 即 `{pk}`：`d:{table}:{pk}` 的 slot = `crc16(pk) % 16384`；
2. `keycodec` 离线预生成 **16384 个 tag 字符串** `stag[i]`，满足 `crc16(stag[i]) % 16384 == i`（格式如 `{s:00042}`，init 时一次性算出存内存数组）；
3. 写入/查询路径中，任何与行同 slot 的辅助 key 使用 `stag[slot(pk)]` 作为 tag；
4. 校验：一致性测试随机抽 key + tag，断言适配器路由目的节点与内核 slot 计算一致（[12](12-测试方案.md) §12.4）。

**等值桶 key 中 `{value}` 的转义**：先 URL escape；超长（>128B）或含 `:`、`{}`、`#` 的值改取 xxhash64 摘要（桶 key 带 `~x` 前缀标记为摘要桶，查询侧同规则寻址）。转义规则只在 keycodec 内实现与测试。

**二级分片注意**：若适配器底层客户端存在"子集群"式二级分片，契约要求其分片函数必须先提取 hash tag——同 tag 的所有 key 必落同一路由域（R1 一致性测试覆盖）。Sweeper 按 slot 区间分摊时以 slot 编号为准而非节点，天然兼容。

## 3.3 桶（Bucket）模型

- 索引 = 每 slot 一组桶，初始 1 桶，零预分片；
- 范围索引桶按 **score 区间** 分裂（`[lo,hi)` 记录在 BucketMap），范围谓词整桶裁剪；
- 等值索引桶按 **pk 的 xxhash64 高位** 分裂为 2 的幂个子桶；
- 字典序副本随同其等值索引分裂（member 为值编码，按值字典序区间分裂）；
- 桶状态机：`ACTIVE → SPLITTING → DRAINING → DELETED`；合并走 `ACTIVE → MERGING → DELETED` 镜像；状态持久于 BucketMap；
- 单桶上限：成员 < 50,000 且体积 < 8MB（触发分裂，见 [08](08-自治治理与热Key.md)）。

## 3.4 编码设计（序列化性能）

原则：能用 Redis 原生结构就不序列化；必须序列化就用代码生成的 msgpack，不用反射。

| 数据 | 存储/编码 | 说明 |
|---|---|---|
| 行·标量字段 | Hash 平铺（`HSET d:t:{pk} name "张三" age 30`） | 零序列化；投影查询 `HMGET` 免解码 |
| 行·嵌套字段（JSON 列） | Hash 单字段 blob | msgp 代码生成版（`tinylib/msgp`），标准 msgpack 格式 |
| 回执 / BucketMap / Catalog / cfg | 单 key blob（Hash 单字段） | 同上 |
| 索引桶 member | 原始字节（pk，或 pk+覆盖列定长分隔编码） | 零序列化 |

数值编码约定：score 字段为 int/float 直存（ZRANGEBYSCORE 语义要求 float64 有序无损；int64 超出 2^53 的字段禁止建范围索引，DDL 校验）；string 走等值索引/字典序副本；时间戳为 Unix 秒。

**单行体积上限（大 key 防线）**：行 Hash 是唯一成员体积不受桶分裂保护的结构。DDL 声明表级 `max_row_bytes`（默认 1MB，硬上限 4MB——必须显著低于 8MB 迁移红线）；写入路径在 Lua 调用前由 txguard 校验序列化后体积，超限返回 `ERR_ROW_TOO_LARGE`。JSON 列是主要风险源，DDL 应引导大对象走对象存储+引用。

选型说明：

- `tinylib/msgp` 替代反射版 msgpack：生成代码、格式标准（存量零迁移、可灰度），性能 3–5×，分配降一个量级；
- 不采用：`bytedance/sonic`（CPU 架构绑定 JIT，维护风险）、FlatBuffers/Cap'n Proto（行太小收益不成立）；
- 进阶项（暂不实施）：schema 感知二进制行编码（字段名→1 字节编号，体积降 30–50%）。仅当 profiling 证明编解码 CPU 占比 >15% 时单独立项，届时需自带 decode CLI 解决 redis-cli 不可读问题。

## 3.5 覆盖索引（可选，按索引声明）

高频投影列可冗余进范围桶 member：`member = pk + "|" + msgpack(col1,col2,...)`，命中时跳过回表。

- 代价：写放大 + 桶体积增速加快（分裂机制自动吸收）；
- 等值桶同理可携带覆盖列（score 仍为 0，member 编码相同规则）；
- 默认关闭，DDL 按索引显式开启：`CREATE INDEX idx ON t(a) COMMENT 'kidb:{"covering":["b","c"]}'`（[02](02-SQL服务器.md) §2.4）；
- 覆盖列变更必须走同步索引（异步索引不允许 COVERING——滞后窗口内覆盖列会返回旧值且回表校验无法发现"值不同但行存在"的场景，属于静默错值，违反结果精确纪律）。

## 3.6 数据量估算示例（1 亿行 / 32 节点）

| 项 | 估算 |
|---|---|
| 行 Hash（均值 200B/行） | ~20GB |
| 单索引桶 member（pk 16B + 编码开销） | 每索引 ~4–6GB（含 ZSet 结构开销） |
| exp 登记册 | ~3GB |
| 回执（仅带 TTL 行，grace 300s 窗口） | 视 TTL 行比例 |
| 元数据（Catalog/BucketMap/锁/计数器） | < 100MB |

内存大头是行与桶，桶的 8MB/5 万成员上限保证单 key 搬迁与命令耗时都有界。

**key 数量放大提醒**：等值索引是"每值每 slot 一桶"，高基数等值索引（如唯一索引，接近每行一个值）的桶 key 数 ≈ distinct 值数 × slot 覆盖度，每个 key 本身有 ~150B 固定开销（key 字符串 + 元数据）。1 亿 distinct 值 ≈ 15GB 纯 key 开销——**高基数字段建等值索引前必须在 DDL 评审中估算此放大**（唯一约束场景除外：唯一性判定走预约 key 机制，[05](05-写入路径.md) §5.3）。范围索引无此问题（桶数 = slot 数 × 分裂代数）。
