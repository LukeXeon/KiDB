# 03 · 数据模型与编码

> **TiDB 参照**：TiDB 行 = `t{tableID}_r{handle}` 一个 KV，索引 = 每条目一个扁平 KV key，范围查询 = 有序迭代
> → Redis 无有序 keyspace 迭代（SCAN 亦被禁），唯一的有序结构是 per-key ZSet → 索引段译成 **ZSet 桶**；
> 行译成 Redis Hash 平铺（TiKV 没有的能力红利：投影查询 `HMGET` 免整行解码）；
> **v7.0：桶按值/索引独立寻址（tag = 编码值/子桶号），与行 slot 解绑**——索引组织与 TiDB 的
> "索引 KV 独立于行位置"同构；行 slot 内聚收窄为"行 + 回执 + 异步日志"（行 Lua 原子性的最小保留面）；
> 唯一索引 key 模型原样保留（每值一 key，value=行 key），见 [05](05-写入路径.md) §5.3。
> key 布局的唯一所有者是 `keycodec` 包（对齐 TiDB `tablecodec` 纪律，[13](13-TiDB复用清单.md) §13.4）：
> 全仓库任何组件不得手工拼接 key 字符串，一律经 keycodec 构造函数生成——布局演进、转义规则、
> 一致性测试都有单一落点。

## 3.1 Key 规范（`{}` 为 hash tag）

| 用途 | Key 格式 | 类型 | TTL | 备注 |
|---|---|---|---|---|
| 行数据 | `d:{table}:{pk}` | Hash（字段 + `_ver` 版本号） | 用户指定 `_ttl`，无则不过期 | keycodec.`RowKey`；`_ver` 兼任索引 member 版本戳源（[05](05-写入路径.md) §5.1） |
| 过期登记册 | `exp:{table}` | ZSet：member=pk，score=到期时间戳（无 TTL=+inf） | 无 | **v7.0 集中单册**（16384 册 → 1）：COUNT(*) = 1 个 ZCOUNT；兼任全表遍历的官方索引（[07](07-TTL与过期清扫.md) §7.4）；细分为规模红线自动项（ROADMAP，不预置阈值） |
| 过期回执 | `rcpt:{table}:{pk}` | Hash：{索引id: "桶key member score"} | 行TTL+300s，清扫后删 | 跟行同 slot（行 Lua 原子面）；member 带版本戳 |
| 等值索引桶 | `i:{table}:{idx}={encVal}`（子桶 tag = `encVal#b{n}`） | **ZSet：member=`pk\x1f_ver`，score=0** | 无 | **v7.0 按值寻址**：tag = `{encVal}`（EscapeValue 已保证无 `:{}#`）；分裂子桶把 `#b{n}` 编入 tag 摊异 slot；Set→ZSet（禁 SCAN 对策，[09](09-后端契约与适配器.md) §9.5） |
| 范围索引桶 | `i:{table}:{idx}:{r子桶号}` | ZSet：member=`pk\x1f_ver`，score=字段值 | 无 | **v7.0 集中**：默认单桶（子桶号 0）；按 score 区间分裂，子桶各占异 slot（[08](08-自治治理与热Key.md)） |
| 字典序副本（前缀搜索用） | `i:{table}:{idx}:{l子桶号}` | ZSet：member=值+pk+ver 编码，score=0 | 无 | `ZRANGEBYLEX`；随同族范围/等值索引分裂 |
| 热桶读副本 | 源桶 key 的 hash tag 步进替换 | ZSet | 60s 滚动续期 | 副本 tag = `SlotTag((源slot + k×1820) % 16384)`（stride=⌊16384/9⌋，k∈[1,8]），确定性异 slot 可寻址（[08](08-自治治理与热Key.md) §8.4） |
| 唯一预约 key | `u:{table}:{idx}={encVal}` | String：占有者行key\|ts | 无 TTL（随回执释放，自愈兜底） | 按值散列路由（v6 起即值寻址形态），[05](05-写入路径.md) §5.3 |
| 异步索引日志 | `log:idx:{table}:{idx}:{stag}` | List | 无 | **保持行 slot 形态**：redo 与行写在同一个行 Lua 内原子落盘（行 Lua 原子面的最后保留地），indexer 跨 slot 应用（幂等） |
| BucketMap | `bm:{table}:{idx}` | Hash（msgp 编码 + version 字段） | 无 | **v7.0 集中每索引一文档**（16384 分片消除——桶不再按行 slot 散布）：热值子桶表（值→K）+ 范围子桶区间表；默认形态由规则推导不落盘 |
| 热值注册表 | `bmh:{table}:{idx}` | Hash（field=值/`@range`/`r4:{桶key}`） | 无 | 读路径稀疏判定；L4 副本登记 |
| 遥测候选 | `hotcand` | Hash（field=桶 key） | 无 | 采样登记，Controller 复核后摘除 |
| Catalog | `c:table:{table}` | Hash（schema/索引定义/TTL 默认 + `_ver`） | 无 | [06](06-元数据与Schema演进.md) |
| 全局 schema 版本 | `ver:schema` | String（INCR） | 无 | 任何 DDL +1；schema lease 的失效锚点（[06](06-元数据与Schema演进.md) §6.2） |
| 全局配置 | `cfg:global` | Hash（变量名→msgp 值 + `_ver` + `_audit`） | 无 | 内置系统表，[10](10-配置与可观测.md) §10.2 |
| 行版本计数器 | `ver:{table}` | String（INCR） | 无 | 分片化见 [08](08-自治治理与热Key.md) §8.6 |
| 自增序列 | `seq:{table}` | String（INCR） | 无 | |
| 桶统计 | `st:{桶key}` | Hash（ops/估算基数） | 短期 TTL 滚动 | |
| 索引基数 HLL | `hll:{table}:{idx}` | HLL | 无 | 索引级单 key（按值 1/64 确定性采样写入；PFCOUNT×64 读侧回补；per-slot 形态的 16384 路扇出无消费方，[04](04-查询路径.md) §4.6） |
| 控制锁 | `lk:ctrl`、`lk:sweep:{slot区间}` | String（token + PX） | PX 自动过期 | `SET token NX PX` |

> 记号说明：`{table}` 是表名占位（裸插值，非 tag）；`{pk}`/`{stag}` 是字面大括号包裹的 hash tag。
> `{stag}` 是"预计算的 slot tag 字符串"而非数字字面量（见 §3.2）。

## 3.2 Hash tag 机制与 slot tag 表（实施关键）

**目标（v7.0 收窄）**：行 slot 内聚只剩"行 + 回执 + 异步日志"——这三者必须在同一个行 Lua 内
原子完成（写入耐久性/原子性的最小保留面）。**索引桶、登记册、BucketMap 不再与行同 slot**：
桶 tag = 编码值（等值）或子桶号（范围/lex），登记册集中单 key，bm 集中单文档。

机制（依赖契约 R1：适配器路由与内核 slot 计算一致，[09](09-后端契约与适配器.md) §9.3）：

1. 行 key 的 tag 即 `{pk}`：`d:{table}:{pk}` 的 slot = `crc16(pk) % 16384`；回执同 tag；
2. `keycodec` 离线预生成 **16384 个 tag 字符串** `stag[i]`，满足 `crc16(stag[i]) % 16384 == i`
  （格式如 `{s:00042}`，init 时一次性算出存内存数组）——**v7.0 用途收窄**：仅异步日志 key
  （`log:idx:…:{stag}`，须与行同 slot 才能入行 Lua）与 L4 副本 tag 步进使用；
3. 等值桶 tag = `{encVal}`：EscapeValue 的摘要规则（>128B 或含 `:`、`{}`、`#` → `~x` 摘要）
  恰好保证转义形态不含 tag 结构字符——桶按值落槽零新机制；
4. 校验：一致性测试随机抽 key + tag，断言适配器路由目的节点与内核 slot 计算一致（[12](12-测试方案.md) §12.4）。

**二级分片注意**：若适配器底层客户端存在"子集群"式二级分片，契约要求其分片函数必须先提取 hash tag——同 tag 的所有 key 必落同一路由域（R1 一致性测试覆盖）。Sweeper 分工以 score 窗口/锁区间为准而非节点，天然兼容。

## 3.3 桶（Bucket）模型（v7.0 重写）

- 等值索引 = **每值一组桶**（按值寻址），初始 1 桶，零预分片；分裂 = 值桶 → K 个子桶
  （`#b{n}` 编入 tag 摊异 slot），写/删按 `xxhash64(pk) % K` 确定性选子桶（撤建同函数可寻）；
- 范围索引 = **每索引一组桶**，初始单桶，按 **score 区间** 分裂（`[lo,hi)` 子桶表记录在
  BucketMap），范围谓词按区间裁剪子桶集；字典序副本同构（按值字典序区间）；
- **member 携带行版本戳** `pk \x1f _ver`（覆盖形态 = msgp 数组含 ver 段）：两段写的并发
  交错安全与幂等重试的全部依据（不变式证明见 [05](05-写入路径.md) §5.1）；
- 桶状态机：`ACTIVE → SPLITTING → DRAINING → DELETED`；合并走 `ACTIVE → MERGING → DELETED`
  镜像；状态持久于集中 BucketMap（每索引一文档）；
- 单桶上限：成员 < 50,000 且体积 < 8MB（触发分裂，见 [08](08-自治治理与热Key.md)）——
  **v7.0 起分裂从优化升格为生产必需**（低基数字段/热值常态集中，靠分裂摊开）。

## 3.4 编码设计（序列化性能）

原则：能用 Redis 原生结构就不序列化；必须序列化就用代码生成的 msgpack，不用反射。

| 数据 | 存储/编码 | 说明 |
|---|---|---|
| 行·标量字段 | Hash 平铺（`HSET d:t:{pk} name "张三" age 30`） | 零序列化；投影查询 `HMGET` 免解码 |
| 行·JSON 列 | Hash 单字段 | 归一化文本（写入时解析归一：key 排序 + float64 数字归一）——可读直查 |
| 回执 / BucketMap / Catalog / cfg | 单 key blob（Hash 单字段） | 同上 |
| 索引桶 member | 原始字节（`pk \x1f _ver`，或 msgp 数组 `[pk, ver, cover...]` 覆盖形态） | 版本戳 = 两段写幂等/交错安全依据（§3.3） |

数值编码约定：score 字段为 int/float 直存（ZRANGEBYSCORE 语义要求 float64 有序无损；int64 超出 2^53 的字段禁止建范围索引，DDL 校验）；string 走等值索引/字典序副本；时间戳为 Unix 秒。

**Catalog 列类型记录（忠实化，v6.0）**：列定义 = 存储类（上表编码规则的选择依据）+ 规范类型文本（gms 解析产物原样，如 `varchar(32)`）。schema 输出按规范文本忠实重建——**varchar 长度全程不丢**（写入侧 gms 类型转换强制长度，MySQL 严格行为；gms 的 MySQL 习惯校验对我们零冲突——docs/02 §2.2）。存储编码与类型文本解耦：文本演进不影响存量数据。

**单行体积上限（大 key 防线）**：行 Hash 是唯一成员体积不受桶分裂保护的结构。上限固定 1MB（`tuning.toml` `txguard.max_row_bytes`——必须显著低于 8MB 迁移红线；不设 DDL 选项，docs/01 §1.0）；写入路径在 Lua 调用前校验序列化后体积，超限返回 `ERR_ROW_TOO_LARGE`。JSON 列是主要风险源，DDL 应引导大对象走对象存储+引用。

选型说明：

- `tinylib/msgp` 替代反射版 msgpack：生成代码、格式标准（存量零迁移、可灰度），性能 3–5×，分配降一个量级；
- JSON 列存**归一化文本**（v6.x review 用户裁决，msgpack 二进制形态回退）：写入时解析归一（key 排序、数字 float64 归一、重复 key 后写胜——MySQL 二进制 JSON 同族纪律），存储形态即可直读文本（HGET 运维可观测性恢复、双格式手卷编解码器删除）；如实声明：数字按 Go float64 最短形式打印（1.0 → "1"，展示级差异），>2^53 整数精度不担保；
- 不采用：`bytedance/sonic`（CPU 架构绑定 JIT，维护风险）、FlatBuffers/Cap'n Proto（行太小收益不成立）；
- 进阶项（暂不实施）：schema 感知二进制行编码（字段名→1 字节编号，体积降 30–50%）。仅当 profiling 证明编解码 CPU 占比 >15% 时单独立项，届时需自带 decode CLI 解决 redis-cli 不可读问题。

## 3.5 覆盖索引（可选，按索引声明）

高频投影列可冗余进范围桶 member：`member = msgp 数组 [pk, ver, cover1, ...]`，命中时跳过回表。

- 代价：写放大 + 桶体积增速加快（分裂机制自动吸收）；
- 等值桶同理可携带覆盖列（score 仍为 0，member 编码相同规则）；
- 默认关闭，DDL 按索引显式开启：`CREATE INDEX idx ON t(a) COMMENT 'kidb:{"covering":["b","c"]}'`（[02](02-SQL服务器.md) §2.4）；
- 覆盖列变更必须走同步索引（异步索引不允许 COVERING——滞后窗口内覆盖列会返回旧值且回表校验无法发现"值不同但行存在"的场景，属于静默错值，违反结果精确纪律）；
- **覆盖列必须 NOT NULL**（DDL 校验）：member 是 msgp 字符串数组，NULL 无法保真（读路径会把 NULL 返回成空串=静默错值）。可空列不声明 covering 即可（回表路径本就正确）；
- **读路径命中条件与活性校验**：投影 ∪ 谓词列 ⊆ {索引列} ∪ 覆盖列 ∪ {pk} 时跳过回表；活性经 `ZSCORE exp:{table}`（集中册，score > now 即活）——过期未清扫行绝不返回；member 解码失败防御性回退回表；member 内 ver 与行 `_ver` 不符 = 脏残留（回表校验等价拦截，对账清理）；
- 在线回填（`_job`）同样经 `EncodeMember` 写覆盖列——回填/写入两路编码一致。

## 3.6 数据量估算示例（1 亿行 / 32 节点）

| 项 | 估算 |
|---|---|
| 行 Hash（均值 200B/行） | ~20GB |
| 单索引桶 member（pk 16B + 编码开销） | 每索引 ~4–6GB（含 ZSet 结构开销） |
| exp 登记册 | ~3GB |
| 回执（仅带 TTL 行，grace 300s 窗口） | 视 TTL 行比例 |
| 元数据（Catalog/BucketMap/锁/计数器） | < 100MB |

内存大头是行与桶，桶的 8MB/5 万成员上限保证单 key 搬迁与命令耗时都有界。

**key 数量放大提醒**：等值索引是"每值一桶"，高基数等值索引（如唯一索引，接近每行一个值）的桶 key 数 ≈ distinct 值数（v7.0 起**无 slot 乘数**——v6 的"× slot 覆盖度"放大随穷举消亡），每个 key 本身有 ~150B 固定开销（key 字符串 + 元数据）。1 亿 distinct 值 ≈ 15GB 纯 key 开销——**高基数字段建等值索引前必须在 DDL 评审中估算此放大**（唯一约束场景除外：唯一性判定走预约 key 机制，[05](05-写入路径.md) §5.3）。范围索引桶数 = 子桶数（分裂代数），无此问题。
