# 11 · 集群适配与部署形态

## 11.1 集群适配矩阵

| 场景 | 行为 |
|---|---|
| slot 迁移 / rebalance | 桶按 slot 编号寻址，随 slot 整体搬迁（单桶 <8MB 有界）；适配器负责 MOVED/ASK 自动重定向与拓扑刷新（契约 R5），内核按 [09](09-后端契约与适配器.md) §9.6 退避矩阵处理重定向耗尽 |
| 节点扩缩容 | 适配器拓扑刷新即生效；方案零数据搬迁、零元数据变更——相对预分片静态方案的代际优势 |
| 客户端二级分片（子集群） | 契约要求同 hash tag 同路由域（[09](09-后端契约与适配器.md) §9.3 R1），同 slot 内聚性保持；按 slot 编号的设计（Sweeper 分摊、登记册遍历）不受影响 |
| 节点宕机 | 该 slot 查询报错（符合预期）；failover 后适配器拓扑刷新自动恢复；failover 窗口的 `READONLY` 错误走退避矩阵 |
| 时钟偏移 | 影响 exp 登记册判定（COUNT 偏差有界并告警）；可选能力 `TIME` 命令做周期校准，偏移超 ±5s 告警 |
| EVAL 被禁 | **不支持，拒绝启动**。EVAL 是硬依赖（[09](09-后端契约与适配器.md) §9.4），启动期能力探测 + 上线前置检查单覆盖 |
| keyspace notification 被禁 | 无影响（加速通道默认关闭，[07](07-TTL与过期清扫.md) §7.3） |
| 适配器不支持副本读 | L3 自动关闭，L1/L2/L4 不受影响（可选能力降级，[09](09-后端契约与适配器.md) §9.4） |

## 11.2 部署形态：MySQL 协议网关单形态

> **形态决策**：产品只交付 **MySQL 协议网关（server-only）**——对标 TiDB 的交付形态：
> 查询层产品以 server 交付（集群或单机部署），不存在"以库形式嵌入业务进程"的支持矩阵。

决策理由：

1. **多语言零成本**：MySQL 协议即接入面，任何语言/驱动/GUI 直接可用；
2. **治理面收敛**：版本统一升级、集中限流审计、连接收敛、后台角色专职于网关集群；
3. **支持矩阵减半**：单一形态砍掉"多壳对齐"的测试、文档与指标/日志一致性纪律；协议兼容层（[02](02-SQL服务器.md) §2.10）是唯一形态的核心投入；
4. **与内核解耦不变**：内核仍是零私有依赖的独立 Go 包，`Querier` 保留为测试与带外工具的程序化入口（工程接缝，不构成第二产品形态——正如 TiDB 可用 mockstore 进程内起实例跑测试，但那不是产品形态）。

代价（诚实声明）与缓解：

| 代价 | 缓解 |
|---|---|
| 新增中间件：网关可用性 = 缓存查询可用性上限 | 网关无状态（共享状态全在 Redis 元数据），多副本 + 标准 LB 部署；对可用性极端敏感的路径允许业务裸 KV 旁路（[14](14-红线局限与检查单.md) §14.2） |
| 点查额外 +0.2~1ms 一跳 | 网关侧近缓存 + 软路由压制；对延迟极端敏感的路径保留裸 KV |
| 进程内近缓存被副本数稀释 | 谓词指纹一致性哈希软路由保持缓存亲和（同指纹查询固定落同副本） |

`Client` 注入点：网关在**构建期链接适配器**（默认 go-redis 参考实现；私有客户端实现 [09](09-后端契约与适配器.md) §9.3 接口后编译进网关镜像），引导参数（地址/池/超时）在启动期构造 `Client`。

后台角色（Controller/Sweeper/Indexer）基于 `lk:ctrl` / `lk:sweep:{区间}` 锁与心跳在网关集群内自动选主/分工（watchdog 闭环，[08](08-自治治理与热Key.md) §8.5），对节点身份无感知——任意副本混跑安全。Bootstrap 唯一相关参数是 `ReadWriteOnly`（纯读写节点：不启动后台角色循环、不参与抢锁），用于低资源实例、边缘只读代理等明确豁免场景；默认参与。

## 11.3 协议兼容层（采纳度生死线）

GUI 工具（DBeaver/Navicat/DataGrip）与各类 MySQL 驱动连接后立即发出握手探测语句，必须礼貌应答否则客户端直接断开——完整矩阵与门禁见 [02](02-SQL服务器.md) §2.10。该层是单形态下的**第一优先级工程项**：客户端连不上，后面所有设计都不存在。

## 11.4 共存与演进纪律

- 元数据/BucketMap/配置格式内嵌版本号，前后兼容一个发布周期（[06](06-元数据与Schema演进.md) §6.4）；
- 内核版本语义化；功能开关走内置配置系统表（`SET GLOBAL`，版本校验热传播，[10](10-配置与可观测.md) §10.2）；
- 新旧内核混跑期间，Lua 模板按 `@version` 隔离（EVALSHA 哈希天然隔离），回滚安全；
- 滚动升级：网关无状态，逐副本替换；**先全量升级网关，再启用依赖新元数据格式的 DDL 能力**（旧实例遇到不认识的格式版本会 fail-fast 拒绝服务，这是设计行为而非故障）；
- 依赖升级纪律：go-mysql-server / TiDB parser / go-redis 任一升级触发全量回归（[12](12-测试方案.md) §12.9），parser 版本基线记录在 [13](13-TiDB复用清单.md) §13.5。
