# 04 · 查询路径

> **TiDB 参照**（推导链见 [13](13-TiDB复用清单.md)）：TiDB 读路径 = Snapshot 点查/有序迭代 + coprocessor 下推 + distsql 扇出
> → Redis 无有序迭代、无快照、无内嵌执行器 → KiDB = 谓词→桶命令翻译 + 参数化 Lua 下推 + Request 对象扇出 + 回表校验。
> 缓存定位：不要 MVCC/快照读——正确性由"回表时重校验"保证，而不是由一致性读保证（[01](01-定位架构与TiDB对齐.md) §1.4）。

> **实现状态**：点查/等值/范围散取 + 回表校验 + 流式护栏 + 谓词下推 Lua 已落地
> （exec 包，P4 双实现比对覆盖）；**top-k 归并（ORDER BY 索引列 ± LIMIT 的全局 score
> 有序流，16384 路 k 路归并）与前缀搜索（字典序副本 ZRANGEBYLEX 归并）已落地**；
> COUNT(*) 无过滤由 gms `replaceCountStar` 规则原生承接（命中 `StatisticsTable`
> 精确 RowCount = exp 登记册 Σ ZCOUNT）；MIN/MAX 经引擎聚合（精确），
> 端点加速的等价写法是 `ORDER BY col LIMIT 1`（top-k 早停）；
> GROUP BY/带过滤 COUNT 由引擎层算子承载（结果精确）。
> v6.0 起网关侧无任何快速路径/文本形状识别（docs/02 §2.2 单引擎纪律）。

## 4.1 谓词 → 命令翻译表（无 SCAN 版）

| SQL | 执行计划 |
|---|---|
| `pk = ?` / `pk IN (...)` | `HGETALL` / 逻辑 pipeline 批量点查（契约 R4，跨 slot 由适配器按节点聚合） |
| `num > a [AND num < b]` | BucketMap 裁剪覆盖桶 → 并发 `ZRANGEBYSCORE bucket lo hi LIMIT off n` |
| `str = 'v'` / `str IN (...)` | 对应值桶并发 `ZRANGE bucket i i+511` 分页拉取（等值桶为 score=0 的 ZSet） |
| `A AND B` | 统计信息选低基数条件取候选，第二条件 pipeline 批量校验（`ZSCORE`：等值桶判存在、范围桶取 score 判区间） |
| `A OR B` | 两路并发，pk 集求并（golang-set/v2） |
| `ORDER BY num LIMIT k` | 沿 score 有序桶从端点 `ZRANGEBYSCORE ... WITHSCORES LIMIT` 归并：种子轮全部覆盖桶端点各取 1 成员建堆（16384 路，与 COUNT(*) 的 Σ ZCOUNT 同形），弹出赢家按需补页；LIMIT 早停由引擎 Limit 节点停止消费自然达成（exec/topk.go，泛型优先级队列 `gopkg.in/dnaeon/go-priorityqueue.v1`） |
| `ORDER BY num DESC LIMIT k` | 同上，`ZREVRANGEBYSCORE` + 大顶堆（gms `lookup.IsReverse` 接线） |
| `COUNT(*)` 无过滤 | `Σ ZCOUNT(exp:{table}:{stag}, (now, +inf))`，16384 个登记册经逻辑 pipeline 按节点聚合，任意时刻精确 |
| 无索引谓词 | 引擎层全扫闸门裁决（docs/07 §7.4）：小表自动放行 / 白名单放行并告警 + `fullscan_fallback_total` 计数 / 否则 `ERR_NO_INDEX`；放行后走 exp 登记册驱动的全表遍历 + 限流通道 |
| 中缀/后缀 `LIKE '%abc%'` | 同上，按无索引谓词处理 |

翻译纪律：所有桶命令必须带 LIMIT 或分页批大小（默认 512），任何路径不允许出现无界命令；任何命令必须携带 key（契约 R2）。

> **范围扫描的有序性契约（gms `replace_sort.go` 分析器规则）**：ORDER BY 列与索引表达式前缀匹配时，gms 直接删除 Sort 节点——ASC 情形不咨询任何接口，DESC/无 WHERE 情形仅查 `OrderedIndex`。等价于约定"索引扫描必须按索引列有序产出"。因此 KiDB 的 RangeLookup **一律**走 k 路归并产出全局 score 序（不依赖对分析器决策的探测）；等值/唯一/主键索引实现 `OrderedIndex.Order()=None` 且 `CanSupport` 只接受点范围，防止 gms 把无序结构选为排序载体（主键范围 ORDER BY 由引擎层 sort 承载——主键无有序结构，如实声明）。

## 4.2 服务端谓词下推（标准能力，非可选）

> TiDB 参照：coprocessor 把 Selection/TopN 下推到 TiKV 节点 → Redis 无内嵌执行器，Lua 是唯一下推载体。

等值/范围的简单谓词组合编译为参数化 Lua 模板（独立 `.lua` 文件，见 [05](05-写入路径.md) §5.7），在节点内完成"取候选 → 回表 → 谓词过滤"，网络只传命中行：

```lua
-- script/lua/pushdown_filter.lua（示意）：范围谓词 + 等值谓词联合下推（同 slot，两轮协议）
-- 轮1（客户端）：ZRANGEBYSCORE 桶key 取候选 pk（带 LIMIT）
-- 轮2（本脚本）：KEYS = 候选行的全部行key（查询时显式声明——集群模式 Lua 禁止访问未声明 key）
--               ARGV = 过滤字段/值
-- 1. 逐 key HGETALL（与桶同 slot，合法）
-- 2. 跳过空 Hash（过期），执行等值过滤，返回命中行
```

契约约束（[09](09-后端契约与适配器.md) §9.3 R3/R7）：

- `numkeys ≥ 1` 且 **KEYS[1] 必须携带目标 slot 的 hash tag**（路由依据）；两轮协议保证轮 2 的所有 key 与轮 1 的桶同 slot；
- 脚本经 script 包注册器执行，EVALSHA 优先、NOSCRIPT 自动回退 EVAL；
- 启动预热（可选）：对已知模板经任意同 slot key 触发一次 `EVALSHA`，让各节点脚本缓存就位；不预热也正确，仅首次多一次 RTT。

收益：无效回表与传输量下降一个量级。约束：仅编译白名单内的简单谓词形态（对齐 TiDB coprocessor 的表达式下推白名单纪律），复杂表达式仍走客户端校验（[12-测试方案.md](12-测试方案.md) P4 双实现比对保证两路径结果一致）。

## 4.3 Request 对象与 scatter-gather（对齐 distsql）

> TiDB 参照：`kv.Request`（`pkg/kv/kv.go`）以单一结构体贯穿执行器→存储：KeyRanges + Concurrency + KeepOrder/Desc + ReplicaRead + MemTracker。
> KiDB 对齐：`planner.Request` 一个对象承载一次扇出的全部参数，不再散落在函数签名里。

```go
// planner.Request：一次查询扇出的完整描述（对齐 kv.Request 形状）
type Request struct {
    Buckets     []Bucket    // 裁剪后的桶集合（≈ KeyRanges）
    Pushdown    *PushdownSpec // 下推谓词编译产物；nil = 客户端校验
    Concurrency int           // 扇出并发上限（默认 64，bulkhead）
    Batch       int           // 回表/pipeline 批大小（默认 512）
    KeepOrder   bool          // ORDER BY 归并
    Desc        bool
    ReplicaRead bool          // L3 副本读（能力存在且策略允许时）
    Deadline    time.Duration // 分支预算（scatter_deadline_headroom × 读超时）
}
```

- **扇出**：按 BucketMap 裁剪后的桶集合 → 按 slot 归并 → 经逻辑 pipeline 发出（契约 R4，适配器按节点聚合）。并发由 conc pool + errgroup + 信号量做 bulkhead；
- **流式**：RowIter 全链路流式：桶游标 → pk 批（512）→ 回表 → 校验 → yield，永不物化全量；
- **取消**：context 取消贯穿桶分页游标与 pipeline（契约 R6）；
- **超时预算**：scatter 各分支预算 + 归并余量必须 < 适配器读超时配置；内核变量 `scatter_deadline_headroom`（默认 0.8）控制预算占比（[10](10-配置与可观测.md)）；
- **回表校验（必须环节，所有索引路径通用）**：批量 `HGETALL` 后 ① 空 Hash = 行过期/不存在 → 静默跳过；② 重执行谓词过滤 → 不通过则跳过。该环节兜底近缓存陈旧、副本滞后、分裂中间态、异步索引滞后的一切场景——**这是无 MVCC 世界的正确性机制**；
- **投影下推**：SELECT 列子集时回表用 `HMGET` 代替 `HGETALL`，减少传输与解码（Redis Hash 平铺的能力红利，TiKV 无此物）。实现：gms `ProjectedTable` 契约（`WithProjections`），行与投影后 Schema 同宽同序；**`PrimaryKeySchema()` 恒返回全量 schema**——gms coster 的统计构造要求索引列在其中（窄 schema 会触发 gms 内部 nil stat panic，实证），`fix_exec_indexes` 显式兼容宽 PrimaryKeySchema（dolt 同形）；
- **覆盖索引读路径**：投影 ∪ 谓词列 ⊆ {索引列} ∪ 覆盖列 ∪ {pk} 时跳过回表——member 解码覆盖列（同步索引 member 与行原子一致），活性经 `ZSCORE exp` 校验（score > now 即活），零行数据传输（[03](03-数据模型与编码.md) §3.5）。

## 4.4 JOIN 支持（v6.0：引擎层全扫闸门裁决）

**执法点迁移（v6.0）**：v5.x 在网关侧用第二解析器做 JOIN 分档；v6.0 起不再有网关侧
SQL 分析，有界性由**全表遍历闸门**（引擎层，任何一侧全扫先过闸门）裁决：

| 形态 | 结果 |
|---|---|
| `a JOIN b ON a.fk = b.pk`（主键/索引查找 join） | 内层经索引点查（无全扫）→ 放行；外层流式扫描需过闸门（下表） |
| 大表 JOIN 小表（维表广播） | 小表（实时行数 < 阈值，tuning `gateway.dimension_max_rows`，默认 10 万）全扫自动放行 → 作为 hash 侧；gms 依表统计选择小表为构建侧 |
| 两张大表非主键关联（外层全扫大表） | 闸门拒绝（`ERR_NO_INDEX`，引导白名单或改写） |
| 半连接 `WHERE a.x IN (SELECT ...)` | 子查询走索引取集合 → 放行；子查询退化为全扫时按闸门裁决 |

闸门规则（引擎层 `Table.PartitionRows` 全扫前调用）：
**小表自动放行（行数 < 阈值）∨ 表白名单（`query_allow_fullscan_tables`）放行并告警**，
否则报错 `ERR_NO_INDEX`（附建索引/白名单建议）。该闸门同时是无索引谓词纪律的落实点——
不再有独立的"JOIN 分档"与"无索引谓词"两套判定，全扫一律过闸。

- 外表行批大小沿用 `scatter_row_batch`（512，tuning.toml）；
- 维表 hash 表由 gms 引擎内存算子承载（行数阈值即内存上界）；
- 测试：小表广播与大表拒绝的路径比对、行数边界、白名单放行告警（[12](12-测试方案.md) §12.5）。

## 4.5 高级查询能力（Redis 原生结构红利）

| 能力 | SQL 形态 | 实现 | 复杂度/语义 |
|---|---|---|---|
| 前缀搜索 | `field LIKE 'abc%'` | 字典序副本桶 `ZRANGEBYLEX [abc [abc\xff`（member=值+pk 编码，score=0），k 路归并产出全局字典序（gms 删 Sort 契约同 top-k；字符串堆 container/heap）；引擎接入经 `IndexSearchableTable.LookupForExpressions`（FilteredTable 在 gms v0.20 只在 bindvar 规则被调用，非常驻分析面） | O(log N + 命中数)；仅前缀，其余 LIKE 走无索引通道并告警 |
| MIN/MAX | `MIN(num)` / `MAX(num)` | 引擎层聚合承载（结果精确）；**端点加速写法：`ORDER BY num LIMIT 1`**——top-k 归并早停，O(桶种子数+脏候选)，无全扫 | 引擎精确；端点写法 O(16384 种子+1) |
| 分组计数 | `GROUP BY 等值字段 + COUNT(*)` | **引擎层聚合承载**（ZCARD 直推已评估不采用：过期未清扫成员会虚增计数，破坏"结果精确"纪律——桶 score=0 无过期信息；若未来要做直推需桶 member 带到期戳） | 引擎精确 |
| 近似去重计数 | `COUNT(DISTINCT field)` | 引擎层精确聚合承载（默认）；HLL 基数面（`PFCOUNT hll:{table}:{idx}` × 采样回补）服务 EXPLAIN/DDL 评审，不接结果面（近似纪律：决策可用、结果必须精确） | 引擎精确；HLL 近似 ~0.8%+采样误差 |
| 深分页 | `LIMIT k OFFSET n` / keyset 分页 | 有序桶 `ZRANGE 起点+n 起点+n+k`；keyset（`WHERE pk > ? ORDER BY pk LIMIT k`）翻译为区间起点，最优路径 | O(n+k)，有界 |
| TTL 自省 | `SELECT _ttl`（显式列出）/ `TTL(pk)` 函数 | `TTL d:{table}:{pk}`；-1=永不过期，-2=不存在 | O(1) |

实现要点：字典序副本的维护写入同一写入 Lua（[05](05-写入路径.md)），在线回填同步产出（`_job` 回填经 `rowcodec.LexMember` 同一编码）；`SELECT *` 不含 `_ttl`，显式列出才返回；全部纳入 PBT 对照 SQLite 验证（近似类断言误差界）。回表校验对前缀路径重判 `HasPrefix`（兜 member 编码边界：值含 `\x00` 的极端情形只影响该值自身分桶序，不产生错行）。

## 4.6 统计与优化器

> **近似与抽样的设计纪律**：结果必须精确，统计可以近似。
>
> - **精确的**：一切查询结果路径——返回行 100% 满足 WHERE（回表校验）、COUNT(*) 任意时刻精确（exp 登记册 ZCOUNT）、唯一约束精确（预约 key 判定）、MIN/MAX/GROUP BY COUNT 为精确值。
> - **近似的**：仅决策依据类统计——COUNT(DISTINCT)（HLL ~0.8%）、Telemetry QPS（1/64 采样，分裂阈值有巨大容错带）、分裂中位数（采样估算）、抽样对账（0.1%）。
> - **为什么**：精确统计需要与统计对象同量级的资源，而这些数值只用于有容错带的判断题。MySQL InnoDB `ANALYZE TABLE`、PostgreSQL 直方图、TiDB 的统计框架（直方图+CM-Sketch+TopN）同为采样/近似——优化器统计从来没有精确的，查询结果从来没有近似的。

- 索引级基数用 Redis HLL：**按值确定性采样**（`xxhash64(idx|value) % 64 == 0`——每个 distinct 值以 1/64 概率整体入样，频率无关），`PFADD hll:{table}:{idx} 编码值`（写 Lua 外单 pipeline，统计非原子性结构）；读侧 `PFCOUNT×64` 回补（`IndexCardinality`，EXPLAIN `cardinality(approx)` 行展示）。已知漂移：UPDATE 新值累积、DELETE 不回收（估值向上漂移，与 HLL 误差同属近似纪律）。**消费方现状（诚实声明）**：基数估算当前只服务 EXPLAIN 展示与 DDL 评审；AND 选路的自动接管（经 LookupForExpressions 合取选低基数索引）留作后续项——当前由 gms coster 均匀统计承载；
- 桶的 score 区间边界即等深直方图（对齐 TiDB 直方图思想，免维护——分裂时天然重估），用于 AND 条件选路与索引选择；
- **已知差距（诚实声明）**：AND 选路理想上需要点频估计（"这个值出现多少次"），HLL 只答基数。TiDB 用 CM-Sketch 答点频。KiDB 用桶级 ZCARD 精确值兜底等值选择率（桶即值域，比 CM-Sketch 还准），跨桶 AND 组合按"低基数优先"启发式；若未来出现选路误判案例，再立项引入极简 CM-Sketch（[14](14-红线局限与检查单.md)）；
- Prepared Statements 经 gms 原生预处理注册表承载（解析复用），并作为防注入标准姿势；v6.0 起无网关侧计划缓存（docs/02 §2.5）。
