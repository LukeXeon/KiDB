# 05 · 写入路径

> **TiDB 参照**：TiDB 一次 INSERT = 事务内缓冲 row key + 全部索引 key，2PC 原子提交
> → Redis 唯一的多 key 原子机制是**单 slot Lua** → 行与其全部索引结构用 hash tag 收到同 slot，
> 一次 `write_row.lua` 完成 TiDB 一个事务做的事。这不是简版 TiDB 事务，是它在 Redis 物理约束下的精确等价物。

## 5.1 单行写入 Lua（同步索引，原子）

**KEYS 布局**：行key、本 slot 涉及的全部索引桶key（含字典序副本）、exp 登记册、cnt 计数器、rcpt 回执——全部经 slot tag 表与行同 slot（[03](03-数据模型与编码.md) §3.2）。

**调用约束**（契约 R3/R7，[09](09-后端契约与适配器.md) §9.3）：`numkeys ≥ 1` 且 **KEYS[1] = 行key**（带 `{pk}` tag，作为路由依据）；脚本内不得访问任何未声明 key；经 script 注册器获得 EVALSHA→NOSCRIPT→EVAL 自动回退。

脚本逻辑（`script/lua/write_row.lua`，INSERT/UPDATE 共用，DELETE 为变体）：

```
1. old = HGETALL 行key
2. 若 old 为空 且 rcpt 存在 → 按回执撤销旧索引条目（主键复活场景）
   若 old 非空（UPDATE）→ 按 old 字段值撤销发生变化的索引条目
     （等值桶：ZREM 旧值桶 member；范围桶：ZREM 旧桶；字典序副本：ZREM 旧 member）
3. HSET 新行各字段；行内 HINCRBY _ver（同 slot，幂等校验免费——v5.0 起默认路径，
   ver:{table} 全局计数器仅低频聚合路径使用，写热点对策见 [08](08-自治治理与热Key.md) §8.6）
4. 按各桶当前状态执行写入规则（状态由 ARGV 传入的 BucketMap 快照给出，
   脚本内用 HGET bm version 做 CAS 校验，版本不符返回 stale 由客户端刷新重试）：
     ACTIVE     → 写本桶           （ZADD 桶 0 pk / ZADD 桶 score pk）
     SPLITTING  → 双写父桶与子桶
     DRAINING   → 只写子桶
5. ZADD exp 登记册 score=到期时间戳（无 TTL 记 +inf）；
   有 _ttl → PEXPIRE 行key；写 rcpt 回执，PEXPIRE rcpt = _ttl*1000 + 300000
   （无 TTL → 有 TTL：补写回执；有 TTL → 无 TTL：删回执、PERSIST 行key）
6. INSERT → INCR cnt；DELETE → DECR cnt
```

DELETE 变体：第 3 步替换为 `DEL 行key`（行 Hash 字段数有界——单表列数上限 DDL 校验 ≤256，DEL 复杂度有界；UNLINK 作为配置项可选）。

**脚本规模控制**：一张表的索引集合在 Catalog 声明，写入前由 txguard 按"行 slot + 各索引当前桶状态"展开 KEYS/ARGV；KEYS 数量 = 1（行） + Σ各索引当前桶数（正常 1/索引，分裂期 3/索引） + 3（exp/cnt/rcpt）。DDL 限制单表索引数 ≤ 16，单次 Lua KEYS ≤ 64。

**返回值协议**：`{status, old_ver, new_ver, stale_flag}`；`stale_flag=1` 时客户端刷新 BucketMap 后整体重试（最多 3 次，指数退避）。

## 5.2 异步索引（写热点字段）

- 写入 Lua 只写行 + `RPUSH log:idx:{table}:{idx}:{stag}`（变更条目：pk、旧值、新值、_ver；Lua 内容量预检前置——无回滚，超限 `log_full` 背压）；
- Indexer 后台消费日志（`LRANGE` 批读 + `LTRIM` 截断）。**v1 实现：桶布局与同步索引一致（行 slot 内聚）**——写热点的摊平体现在写路径轻量化（Lua 不碰热桶、Indexer 批量消费），桶寻址与查询路径零分叉；（v4 曾写"pk 全局散列异 slot 桶"，实现期评估为不必要的寻址分叉——热度摊平的真实来源是行 slot 本身按 pk CRC16 散列）
- 语义：最终一致（秒级）。新行短暂查不到，旧行残留由回表校验消除——**不会出错行**；
- 日志容量上限 10 万条/slot：写入 Lua 内 `LLEN` 检查，**超硬上限直接返回 `ERR_INDEX_LOG_FULL` 背压写入方**（业务可感知报错，而不是集群默默撑爆）；80% 水位告警；消费采用 `LTRIM` 而非逐条 `LPOP`（批操作有界）；
- 同步→异步在线切换：BucketMap 标志位，双写过渡一个周期（旧索引读路径保留至日志追平）；
- 异步索引不允许 COVERING（[03](03-数据模型与编码.md) §3.5）。

## 5.3 唯一约束（预约 key：TiDB 唯一索引的 Redis 实现）

> **TiDB 参照**：TiDB 唯一索引 = 每个值一个 KV key（`t{tid}_i{iid}{val}` → handle），靠事务提交的原子性检测冲突。
> KiDB 原样采用这个模型——**每个唯一值一个预约 key**；差别只在冲突检测的原子性来源：TiDB 靠 2PC，Redis 跨 slot 无事务，
> 靠 `SET NX` 的互斥语义 + 占有者活检查 + 自愈。这是翻译，不是发明。

唯一索引必须同步模式。冲突检测 = 预约 key 两阶段：

1. 写入前：`SET u:{table}:{idx}={encVal} rowKey|ts NX`——key 只由值决定（同值必同 key 同 slot，NX 天然互斥）；
2. NX 失败 → GET 读占有者行 key → EXISTS 判活：活 → `ERR_DUPLICATE_KEY`（映射 MySQL 1062）；占有行已死（过期未清扫）→ DEL 自愈重占；
3. 写入 Lua 提交时预约 key 并入回执（`__uniq` 条目）；行删除/过期清扫时按回执 DEL 预约 key 释放（预约 key 与行异 slot，释放在 slot Lua 外单独执行——失败残留由第 2 步自愈兜底，不会错杀活行的预约）；upsert 族仅在实际写入（affected>0）时释放被替换值的旧预约。

已知窗口（如实声明）：T1 预约成功到写入提交之间（约 1 RTT），T2 冲突检查见占有行不存在会自愈抢占——并发同值冲突双方可能都提交，且不可自愈。该窗口需并发同值冲突恰好交错才触发；强约束场景应由业务侧串行化或加业务锁。**缓存定位下这是可接受的诚实取舍**——要强唯一约束的数据不该只活在缓存里。

## 5.4 UPSERT 与 AUTO_INCREMENT

- **UPSERT**：`INSERT ... ON DUPLICATE KEY UPDATE` / `REPLACE` 映射到 §5.1 同一写入 Lua——脚本本就先读旧行判断插入/更新分支，仅增加"冲突时按 SET 子句合并字段"分支；`INSERT IGNORE` 同理（旧行存在则跳过返回）；
- **AUTO_INCREMENT**：表级计数器 `seq:{table}`，写入 Lua 前单独 `INCR` 取值填主键列；`LAST_INSERT_ID()` 由会话状态返回（[02](02-SQL服务器.md) §2.5）。与 `_ver` 独立；
- 注意 `seq:{table}` 与行不同 slot——`INCR seq` 必须先于写入 Lua 单独执行（跨 slot 不能进同一脚本），竞争安全（INCR 本身原子）。序列值可能因写入失败出现空洞，语义与 MySQL 一致（不保证连续）。

## 5.5 DML 语义表

| 场景 | 结果 |
|---|---|
| INSERT 主键已过期 | 视为全新插入，旧索引残留经回执原子清除 |
| UPDATE/DELETE 命中已过期行 | `0 rows affected` |
| 多行 DML 跨 slot | 逐行执行（行级并发，bulkhead 限制），失败返回部分成功明细，无整体回滚（无事务定位，[02](02-SQL服务器.md) §2.1） |
| 唯一冲突 | 标准 MySQL duplicate key 错误（`ERR_DUPLICATE_KEY` 映射 1062） |
| BucketMap 版本过期 | stale → 客户端刷新重试 ≤3 次，仍失败返回 `ERR_STALE_METADATA` |
| Lua 执行中途节点宕机 | EVAL 原子性：要么全成要么全不成；重试由幂等性保证（`old_ver` 校验防重复应用） |

## 5.6 写入幂等性（重试安全）

MOVED 重定向与业务重试都可能导致同一写入到达两次。保证：

1. 写入 Lua 内校验行内 `_ver`：ARGV 携带**本次预读观察到的** old_ver，Lua 内再读不符说明预读→提交间有并发写入——返回 stale，网关以新鲜旧行**重新展开撤销/重建描述符**后整体重试（≤3 次；ZSet member 去重天然幂等，不产生重复索引条目）。另有调用方 CAS 写语义：`ExpectedOldVer` 非 nil 时预读版本不符即 fail-fast（`ERR_STALE_METADATA`），不重试——实现见 txguard 包；
2. cnt 计数器允许短暂漂移，由对账任务周期校准（[12](12-测试方案.md) §12.7），不参与查询正确性；
3. exp 登记册 ZADD 同 member 覆盖 score，天然幂等。

## 5.7 Lua 脚本资产管理（独立文件 + embed）

**纪律：所有 Lua 脚本以独立 `.lua` 文件存在于 `script/lua/` 目录，经 Go `embed` 包嵌入二进制（embed 指令要求文件在包目录内，故 lua 目录随 script 包）。禁止在 Go 源码里拼接 Lua 字符串。**

目录布局：

```
script/lua/
  write_row.lua        # 单行写入（INSERT/UPDATE/DELETE/UPSERT 全分支）
  sweep_batch.lua      # Sweeper 单 slot 清扫批
  split_migrate.lua    # 分裂搬迁批（含 EXISTS 行key 顺路清理）
  bucket_state_cas.lua # 桶状态机 CAS 步进（BucketMap version 校验）
  pushdown_filter.lua  # 服务端谓词下推
  replica_refresh.lua  # L4 副本重建
  lock_release.lua     # 锁释放（token 比对）
  lock_renew.lua       # 锁续期
  config_set.lua       # SET GLOBAL 的 _ver CAS 原子更新
```

每个文件带头部元数据注释，启动期解析：

```lua
-- @name write_row
-- @version 3
-- @keys_desc KEYS[1]=row_key(router); KEYS[2..n-3]=bucket_keys; KEYS[n-2]=exp; KEYS[n-1]=cnt; KEYS[n]=rcpt
-- @idempotent true
```

加载与校验（script 包）：

1. `//go:embed lua` 嵌入整个目录；init 期遍历解析头部元数据，计算 SHA1（EVALSHA 用）；
2. **静态校验（fail-fast）**：脚本文本不得出现 `scan`/`sscan`/`hscan`/`zscan`/`keys`/`multi`/`exec`/`watch` 调用（禁 SCAN 纪律的最后一道闸）；`numkeys` 必须 ≥1；
3. 启动期压缩：自写 lexer 级去注释/空白薄层（Go 生态无现成 Lua minifier），EVAL 下发字节量 -42%；
4. 版本隔离：模板升级改 `@version`，EVALSHA 哈希天然隔离新旧版本，回滚安全；
5. 单测直接对 miniredis 执行文件内容（[12](12-测试方案.md) §12.2），保证"文件即事实"。
