# 05 · 写入路径

> **TiDB 参照**：TiDB 一次 INSERT = 事务内缓冲 row key + 全部索引 key，2PC 原子提交；索引 KV 按
> `index_id+编码值` 独立寻址，与行落在哪个 Region 无关
> → **v7.0 同构形态**：行本地 Lua（行+回执+异步日志，单 slot 原子）+ 索引命令组（按值/索引寻址，
> 跨 slot 客户端 pipeline）——与 TiDB 的差异仅剩无 2PC 的收敛窗口（§1.8 一致性规格）；
> 并发交错与重试的正确性由 **版本戳 member** 保证（§5.1 不变式）。

## 5.1 两段写协议（v7.0）与行本地 Lua

**总形态**：

```
[唯一索引存在时] 轮 0：SET NX 预约（§5.3；异 slot，冲突即 1062，占有者=行 key 重试自识别）
主 pipeline（一次发出，全部响应收齐才回 OK——正常路径零窗口）：
  ① 行本地 Lua（write_row v7）：读旧行（值+_ver）→ 写行/回执/异步日志 → HINCRBY _ver
  ② 索引命令组（按 ① 返回的 old/new 值与 ver 构造，异 slot）：
     撤旧 ZREM 桶 旧member / 建新 ZADD 桶 新member（含字典序副本）
  ③ 登记册 ZADD/ZREM（集中册 exp:{table}，异 slot）
```

主 pipeline 任何一段失败（重试矩阵耗尽）→ **报错**（Redis 命令失败语义，不静默降级）；
客户端重试幂等收敛（下述）。进程崩溃类无人收错误的窗口 → 对账观测 + 清扫/补写收敛
（[12](12-测试方案.md) §12.8）。

**行本地 Lua 的 KEYS 布局（v7.0 收窄）**：行key、回执key、异步日志key（仅声明为异步的索引
存在时）——**全部与行同 slot，是行 Lua 原子面的最小保留面**。索引桶/登记册/BucketMap
不再出现在 KEYS 中。

脚本逻辑（`script/lua/write_row.lua` v7，INSERT/UPDATE 共用，DELETE 为变体）：

```
1. old = HGETALL 行key（含旧 _ver；ARGV 携带预读 old_ver 做乐观锁，不符返回 stale）
2. 若 old 为空 且 rcpt 存在 → 返回回执内容（主键复活场景，客户端展开撤销命令组）
   若 old 非空（UPDATE）→ 返回 old 字段值（客户端按字段级差异展开撤/建命令）
3. HSET 新行各字段（UPDATE 置 NULL = HDEL 撤字段面，旧有新无）；
   行内 HINCRBY _ver 得 newVer（版本序 = 行写序，无需时钟）
4. ZADD 不在此处——exp/桶全部移出（②③ 客户端段）；
   有 _ttl → PEXPIRE 行key；写 rcpt 回执（撤销信息 = 桶key + 旧member + score），
   PEXPIRE rcpt = _ttl*1000 + 300000（无 TTL → 有 TTL：补写回执；有 → 无：删回执、PERSIST 行key）
5. 声明为异步的索引：RPUSH log:idx:{table}:{idx}:{stag}（redo 与行写同 Lua 原子，§5.2）
```

DELETE 变体：第 3 步替换为 `DEL 行key`（列数上限 DDL 校验 ≤256，DEL 复杂度有界）。

**版本戳 member：并发交错下不漏行的不变式（正确性核心）**

两段化后索引命令与行写不再原子。设并发 `upd1: 值 A→B`、`upd2: 值 B→A`：行 Lua 串行
（upd2 终态 A），但索引命令跨节点无顺序保证——若 upd1 的 `ZREM A桶 pk` 延迟到 upd2 的
`ZADD A桶 pk` 之后到达，A 桶成员被误撤 = **漏行**（行值是 A，查 A 查不到）。

解法：**member = `pk \x1f _ver`**（`_ver` 行内 HINCRBY 单调，v6 已有）：

- ZREM 只撤**精确旧 member**（`pk|oldVer`），ZADD 建**新 member**（`pk|newVer`）——
  不同版本是不同 member，任何延迟/交错**互不误撤**；
- 不漏证明：最高 ver 写的 ZADD 所建 member，不存在任何能撤它的 ZREM（ZREM 只由
  "读到旧 ver"的写产生，目标 member 恒为旧 ver）；
- 残留的旧 ver member 是脏数据（"多"，永不"少"）→ 读侧回表校验滤除（行 `_ver`/值不符）
  + 同 pk 多 member 由 seen 去重 + 对账按 ver 清理（[12](12-测试方案.md) §12.8）；
- ZADD/ZREM 对精确 member 天然幂等 → 重试安全；INSERT 重试撞自己预约 → 占有者比对
  自识别放行；DELETE 方向对称（失败只留脏不留漏）。

**分裂窗口的迟到写收容（bm 快照过期安全）**：v6 在写 Lua 内做 bm 分片版本 CAS；v7 bm 集中，
CAS 移出 Lua——写入按"客户端 bm 快照（1s 缓存）"构造索引命令。快照过期时写可能落在旧父桶：
分裂状态机以 **DRAINING 排干循环**收容——父桶不排空不得 DELETED，迟到 member 由排干循环
迁移进子桶（版本戳使迁移幂等）；客户端缓存 1s 内必然刷新，迟到写有界。 bm 文档的并发
步进由 `bucket_state_cas.lua`（集中 bm key 上单 slot CAS）仲裁。

**返回值协议**：`{status, old_ver, new_ver, old_fields...}`（status ∈ ok/stale/log_full）；
stale 时客户端以新鲜旧行重新展开命令组整体重试（≤3 次，指数退避）。

## 5.2 异步索引（写热点字段）

- 写入 Lua 只写行 + `RPUSH log:idx:{table}:{idx}:{stag}`（变更条目：pk、`\x1f`、`url.QueryEscape(旧值)`、`\x1f`、`url.QueryEscape(新值)`、`\x1f`、_ver——**可逆转义**（v6.x review 修复：此前复用 keycodec 摘要转义，不可逆摘要让 Indexer 二次转义建出与查询侧错位的桶 key，含空格/中文值永久不可见）；Indexer 解回原始值再按 keycodec 规则建桶；Lua 内容量预检前置——容量随 tuning `txguard.async_log_capacity` 经 ARGV 传入，无回滚，超限 `log_full` 背压）；**v7.0：日志 key 保持行 slot 形态——redo 与行写在同一个行 Lua 内原子落盘（行 Lua 原子面的最后保留地）**；
- Indexer 后台消费日志（`LRANGE` 批读 + `LTRIM` 截断）。**实现：桶按值/索引寻址（与同步索引 v7 形态一致）**——Indexer 跨 slot 应用 ZADD/ZREM（版本戳 member，幂等重放），查询路径与索引模式零分叉；热度摊平体现在写路径轻量化（行 Lua 不碰桶、Indexer 批量消费）；
- 语义：最终一致（秒级）。新行短暂查不到，旧行残留由回表校验消除——**不会出错行**；
- 日志容量上限 10 万条/slot：写入 Lua 内 `LLEN` 检查，**超硬上限直接返回 `ERR_INDEX_LOG_FULL` 背压写入方**（业务可感知报错，而不是集群默默撑爆）；80% 水位告警；消费采用 `LTRIM` 而非逐条 `LPOP`（批操作有界）；
- 同步→异步在线切换：BucketMap 标志位，双写过渡一个周期（旧索引读路径保留至日志追平）；
- 异步索引不允许 COVERING（[03](03-数据模型与编码.md) §3.5）。

## 5.3 唯一约束（预约 key：TiDB 唯一索引的 Redis 实现）

> **TiDB 参照**：TiDB 唯一索引 = 每个值一个 KV key（`t{tid}_i{iid}{val}` → handle），靠事务提交的原子性检测冲突。
> KiDB 原样采用这个模型——**每个唯一值一个预约 key**；差别只在冲突检测的原子性来源：TiDB 靠 2PC，Redis 跨 slot 无事务，
> 靠 `SET NX` 的互斥语义 + 占有者活检查 + 自愈。这是翻译，不是发明。

唯一索引必须同步模式。冲突检测 = 预约 key 两阶段：

1. 写入前：`SET u:{table}:{idx}={encVal} rowKey|ts NX`——key 只由值决定（同值必同 key 同 slot，NX 天然互斥）；
2. NX 失败 → GET 读占有者行 key → EXISTS 判活：活 → `ERR_DUPLICATE_KEY`（映射 MySQL 1062）；占有行已死（过期未清扫）→ DEL 自愈重占；
3. 写入提交后预约 key 并入回执（`__uniq` 条目）；行删除/过期清扫时按回执 DEL 预约 key 释放（预约 key 与行异 slot，释放在行 Lua 外单独执行——v7.0 起与全部索引命令同段，失败残留由第 2 步自愈兜底，不会错杀活行的预约；释放前 GET 占有者比对，v6.x review 修复）；upsert 族仅在实际写入（affected>0）时释放被替换值的旧预约。

**存量面（v6.x review 修复——此前 CREATE UNIQUE INDEX 对存量行不建预约，存量值对唯一约束不可见）**：
`CREATE UNIQUE INDEX` 在非空表上先**同步存量查重**（全扫流式去重，命中即 1062 拒建；
distinct 超 `l2_max_collect` 拒建——诚实红线），回填作业为每个存量行补建预约；
回填期预约与并发写入交错产生真实重复时作业中止并回滚索引定义（MySQL 在线 DDL 收尾失败同款语义，告警 + `ddl_job_duration_seconds{type=create_index_abort}`）。

已知窗口（如实声明）：T1 预约成功到写入提交之间（约 1 RTT），T2 冲突检查见占有行不存在会自愈抢占——并发同值冲突双方可能都提交，且不可自愈；写入歧义超时（EVAL 或已提交）后的预约回滚经占有者比对降级，残留由对账 `uniq_reservation_missing`/`uniq_reservation_residual` 双向观测（[12](12-测试方案.md) §12.8）。该窗口需并发同值冲突恰好交错才触发；强约束场景应由业务侧串行化或加业务锁。**缓存定位下这是可接受的诚实取舍**——要强唯一约束的数据不该只活在缓存里。

## 5.4 UPSERT 与 AUTO_INCREMENT

- **UPSERT**：`INSERT ... ON DUPLICATE KEY UPDATE` / `REPLACE` 映射到 §5.1 同一写入 Lua——脚本本就先读旧行判断插入/更新分支，仅增加"冲突时按 SET 子句合并字段"分支；`INSERT IGNORE` 同理（旧行存在则跳过返回）；
- **AUTO_INCREMENT**：表级计数器 `seq:{table}`，写入 Lua 前单独 `INCR` 取值填主键列；`LAST_INSERT_ID()` 由会话状态返回（[02](02-SQL服务器.md) §2.5）。与 `_ver` 独立；
- 注意 `seq:{table}` 与行不同 slot——`INCR seq` 必须先于写入 Lua 单独执行（跨 slot 不能进同一脚本），竞争安全（INCR 本身原子）。序列值可能因写入失败出现空洞，语义与 MySQL 一致（不保证连续）。

## 5.5 DML 语义表

| 场景 | 结果 |
|---|---|
| INSERT 主键已过期 | 视为全新插入，旧索引残留经回执展开的撤销命令组精确清除（版本戳幂等） |
| UPDATE/DELETE 命中已过期行 | `0 rows affected` |
| 多行 DML 跨 slot | 逐行执行（行级并发，bulkhead 限制），失败返回部分成功明细，无整体回滚（无事务定位，[02](02-SQL服务器.md) §2.1） |
| UPDATE 置 NULL | 生效（行 Lua 撤字段面 HDEL 旧有新无字段——v6.x review 修复幽灵残留） |
| UPDATE 改主键撞活行 | 1062 判重（预读）；判重→删旧写新两步非原子，并发交错窗口与 §5.3 同族声明 |
| 唯一冲突 | 标准 MySQL duplicate key 错误（`ERR_DUPLICATE_KEY` 映射 1062） |
| BucketMap 快照过期 | 迟到写由分裂 DRAINING 排干循环收容（§5.1）；客户端缓存 1s 内收敛，无 stale 报错面（bm CAS 已移出行 Lua） |
| 行 Lua 执行中途节点宕机 | EVAL 原子性：要么全成要么全不成；重试由幂等性保证（`old_ver` 校验防重复应用） |
| 主 pipeline 第二段失败（重试耗尽） | **报错**（Redis 命令失败语义）；重试幂等收敛（版本戳精确 member）；崩溃类窗口由对账/补写收敛 |

## 5.6 写入幂等性（重试安全）

MOVED 重定向与业务重试都可能导致同一写入到达两次。保证：

1. 行 Lua 内校验行内 `_ver`：ARGV 携带**本次预读观察到的** old_ver，Lua 内再读不符说明预读→提交间有并发写入——返回 stale，网关以新鲜旧行**重新展开撤销/重建命令**后整体重试（≤3 次）。另有调用方 CAS 写语义：`ExpectedOldVer` 非 nil 时预读版本不符即 fail-fast（`ERR_STALE_METADATA`），不重试——实现见 txguard 包；
2. **索引命令组对精确 member 幂等**（`pk \x1f _ver`，§5.1 不变式）：ZADD/ZREM 重复应用无副作用，并发交错互不误撤；
3. exp 登记册 ZADD 同 member 覆盖 score，天然幂等。

## 5.7 Lua 脚本资产管理（独立文件 + embed）

**纪律：所有 Lua 脚本以独立 `.lua` 文件存在于 `script/lua/` 目录，经 Go `embed` 包嵌入二进制（embed 指令要求文件在包目录内，故 lua 目录随 script 包）。禁止在 Go 源码里拼接 Lua 字符串。**

目录布局：

```
script/lua/
  write_row.lua        # 行本地写（v7：行/回执/异步日志；INSERT/UPDATE/DELETE/UPSERT 全分支）
  sweep_batch.lua      # Sweeper 行 slot 清扫批（行/回执面；桶清理为客户端异 slot 段）
  split_migrate.lua    # 分裂搬迁批（含 EXISTS 行key 顺路清理）
  bucket_state_cas.lua # 桶状态机 CAS 步进（集中 BucketMap 文档 version 校验）
  pushdown_filter.lua  # 服务端谓词下推
  replica_refresh.lua  # L4 副本重建
  lock_release.lua     # 锁释放（token 比对）
  lock_renew.lua       # 锁续期
  config_set.lua       # SET GLOBAL 的 _ver CAS 原子更新
```

每个文件带头部元数据注释，启动期解析：

```lua
-- @name write_row
-- @version 3
-- @keys_desc KEYS[1]=row_key(router); KEYS[2..n-2]=bucket_keys; KEYS[n-1]=exp; KEYS[n]=rcpt
-- @idempotent true
```

加载与校验（script 包）：

1. `//go:embed lua` 嵌入整个目录；init 期遍历解析头部元数据，计算 SHA1（EVALSHA 用）；
2. **静态校验（fail-fast）**：脚本文本不得出现 `scan`/`sscan`/`hscan`/`zscan`/`keys`/`multi`/`exec`/`watch` 调用（禁 SCAN 纪律的最后一道闸）；`numkeys` 必须 ≥1；
3. 启动期压缩：自写 lexer 级去注释/空白薄层（Go 生态无现成 Lua minifier），EVAL 下发字节量 -42%；
4. 版本隔离：模板升级改 `@version`，EVALSHA 哈希天然隔离新旧版本，回滚安全；
5. 单测直接对 miniredis 执行文件内容（[12](12-测试方案.md) §12.2），保证"文件即事实"。
