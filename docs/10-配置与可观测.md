# 10 · 组件选型、配置（内置系统表）与可观测性

## 10.1 组件选型（全部开源，无公司私有依赖）

纪律：只引泛型/stdlib 接口库；并发与缓存优先 Go 官方扩展与大厂自用开源；能用 Redis 服务端能力就不引客户端库；**v6.0 起对 TiDB 零代码依赖**——设计移植保留，直接依赖移除（[13](13-TiDB复用清单.md) §13.3）。

| 组件 | 模块路径 | 验证版本 | 备注 |
|---|---|---|---|

> **审计注记**：本表与 go.mod 严格对齐——选型评估过但当前未 import 的库不在表内（singleflight/errgroup/conc/ants/golang-set/priorityqueue/btree/x-time-rate/toxiproxy：对应能力在 ROADMAP 在案，落地时才引入依赖）。文档不承诺"将用"，只记录"在用"。

自写薄层：分布式锁（~30 行，`SET NX PX` + `lock_release.lua`/`lock_renew.lua`）、BucketMap 版本校验、Lua 脚本注册器（embed 加载 + 启动期压缩）、slot tag 表（sigurn/crc16）、配置存储（§10.2）、近缓存底座 otter（[08](08-自治治理与热Key.md) §8.4）、泛型容器（`ds/`：container/heap 的泛型优先队列封装等——v6.0 工具收敛面，替代第三方微库）。

**配置面的两层分工**：面向用户的运行时配置即数据，存 Redis 自身（§10.2，变量仅 3 个语义开关）；面向开发者的调优参数收 `tuning/tuning.toml`（go-toml/v2 解析，embed 随二进制发布）——除此之外不引入配置解析库。

## 10.2 配置即数据：内置系统表（集群共享一份配置）

**设计动机**：本地配置文件对集群没有意义——N 个网关实例各持一份 TOML 必然漂移。KiDB 的元数据（Catalog/BucketMap）本来就存在 Redis 里、走"本地缓存+版本校验"，配置走完全相同的道路：**一个集群，一份配置，SQL 即管理面**（对齐 TiDB 的 `mysql.*` 系统表定位，但存储落 Redis 而非 TiKV）。

### 存储

| Key | 类型 | 内容 |
|---|---|---|
| `cfg:global` | Hash | field=变量名，value=msgp 编码值；特殊字段 `_ver`（单调递增版本）、`_audit`（最近修改者/时间） |

### SQL 管理面（gms 原生系统变量，v6.0 起无网关拦截）

KiDB 变量注册为 gms 原生 `sql.MysqlSystemVariable`（Dynamic + Global 作用域 + `NotifyChanged` 钩子）：

```sql
SHOW GLOBAL VARIABLES LIKE 'replica\_read';
SET GLOBAL query_allow_fullscan_tables = 't1,t2';
SELECT @@global.hotkey_row_cache;
```

- `SET GLOBAL` 经 gms 校验与作用域处理，`NotifyChanged` 钩子把新值持久化到 `cfg:global`（`config_set.lua` CAS + `_ver` + `_audit`）——钩子经会话携带的配置存储句柄找到本实例存储（多实例各写各的探测点，经 `_ver` 轮询秒级收敛）；
- `SHOW [GLOBAL] VARIABLES` / `SELECT @@global.x` 由 gms 原生服务；
- ro 账号 SET GLOBAL 在钩子内拒绝（引擎层 `RejectRO`）；
- `SET SESSION` 会话级覆盖不落盘（gms 语义）。

> **命名纪律**：变量名一律小写下划线（`max_connections` 同款 MySQL 惯例）。不用点号——`SET GLOBAL a.b = 1` 中的点号有被解析器当成"库.表.列"限定标识符的风险。

### 一致性与传播

- `SET GLOBAL` 经 `config_set.lua` 原子执行：校验期望 `_ver`（CAS）→ HSET 新值 → `_ver+1` → 追加 `_audit`；并发写冲突返回 stale 由客户端重试；
- 各实例本地缓存配置快照，与 Catalog/BucketMap 共用同一版本校验刷新循环（秒级传播，[06](06-元数据与Schema演进.md) §6.2）；查询路径按 1/64 采样顺带校验 `_ver`，热点变更快速收敛；
- 配置 schema 版本内嵌，前后兼容一个发布周期（同元数据演进纪律，[06](06-元数据与Schema演进.md) §6.4）。

### 变量表（全部天然热更新）

**纪律（docs/01 §1.0 设计原点）：变量只承载改变语义的选择，个位数封顶。**
调优参数（阈值/批大小/退避/限速）一律是内置常量，不设变量——运维心智对标 Redis 原生。

| 变量 | 默认 | 说明 |
|---|---|---|
| `query_allow_fullscan_tables` | `''`（全禁） | 全表遍历表白名单（逃生门，逗号分隔，[07](07-TTL与过期清扫.md) §7.4） |
| `replica_read` | `false` | L3 副本读开关（适配器能力位缺失时自动无效，[09](09-后端契约与适配器.md) §9.4） |
| `hotkey_row_cache` | `false` | 行级读热点近缓存（陈旧窗口语义，[08](08-自治治理与热Key.md) §8.4 覆盖边界） |

### 内置常量（开发者调优面：`tuning/tuning.toml`）

**全部开发者调优参数集中在 `internal/tuning/tuning.toml`**（go:embed 进二进制，
启动期加载+红线校验；改动需重新构建发布，不热更）。层级按组件分：
`gateway / nearcache / exec / controller / sweeper / txguard / telemetry / hll / meta / retry`。
数值口径即下表（文档与文件同源，以文件为准）：

| 分组 | 关键项（默认） |
|---|---|
| gateway | 小表全扫放行/维表广播行数上限 10 万 |
| nearcache | L1 3s/1 万条；行缓存 3s/1 万条 |
| exec | 批 512、slot 组宽 64、全扫并发 10、L2 物化上限 2^20、归并补页 16 |
| controller | 分裂 5 万成员/8MB/40% QPS、合并 12500×3 周期、L4 副本 ≤8/1s 刷新、回填 1 万行/s |
| sweeper | 批 512、每 tick 4 批、回执宽限 300s、区间 1024 slot |
| txguard | stale 重试 3、异步日志 10 万/80% 水位 |
| telemetry / hll | 采样 1/64（**数据语义常量**：改动改变存量统计口径，发布说明须注明） |
| meta / retry | schema 租约 1000ms；退避 50ms→2000ms×3 |

校验规则（SET 时执行，非法值拒绝）：`query_allow_fullscan_tables` 表名格式；布尔变量只收 true/false；**未注册变量一律报错**（含历史调优变量——它们已在 tuning.toml）。

### 引导配置（进程级、不可共享、不落配置文件）

连接地址/凭据、连接池大小、读写超时、监听端口、账号表、TLS 开关、ReadWriteOnly——这些描述的是"这个进程怎么连上集群、怎么对外服务"，天然不属于共享配置。经 `NewKernel` 的 Bootstrap 注入（网关由启动参数/环境变量构造，见 `cmd/kidb-server`）。启动校验：`scatter` 预算 = `read_timeout × deadline_headroom`，超限拒绝启动。

## 10.3 指标体系

> **实现状态**：`metrics` 包落地全部系列（prometheus Registerer 注入，nil=no-op）；
> 已挂钩子：查询时长/扇出（exec）、回表校验拦截、L1 命中、stale 重试（txguard）、
> 清扫量（sweeper）、分裂/合并计数与角色变迁（controller）。

内核指标（prometheus，经接口注入）：

`query_duration_seconds{plan}`、`query_scatter_fanout`、`index_bucket_members{table,idx}`、`index_bucket_splits_total` / `merges_total`、`hotkey_replicas_active`、`sweeper_lag_rows` / `swept_total`、`nearcache_hit_ratio`、`async_index_log_backlog`、`rowiter_rows_filtered_total`（回表校验拦截量）、`fullscan_fallback_total`、`lua_stale_retry_total`（BucketMap version 冲突重试）、`lua_noscript_total`（EVALSHA miss 回退）、`config_set_total{result}`（配置变更/冲突计数）、`schema_lease_refresh_total`、`ddl_job_duration_seconds{type}`、`contract_violation_total`（CROSSSLOT 等契约违例，应为 0）、`owner_role_transitions_total`（角色进出次数，watchdog 有效性观察）。

适配器层命令级 QPS/延迟/错误由适配器自带（go-redis 可接 otel/prometheus hook），与内核指标用同一集群标识 label 关联。

## 10.4 慢查询观测与 EXPLAIN（v6.0 简化裁决）

**无逐语句慢查询文本日志**——指纹归一化需要解析 SQL，与单引擎纪律冲突
（docs/02 §2.2）。观测面由两层承接：

- **指标**：`query_duration_seconds{plan}` 直方图（执行器按访问路径分桶）+
  `fullscan_fallback_total`（全扫白名单放行计数）；
- **引擎层全扫告警**：闸门放行白名单全扫时记结构化告警（表/行数），
  这是唯一保留文本日志的慢路径（全扫即异常事件，天然低频）。

EXPLAIN 走 gms 原生（计划树展示，docs/02 §2.6）；KiDB 侧细节经
`Index.String()` 等 gms 展示面透出。双层定位不变：Redis 命令级慢日志
（适配器侧）与 SQL 执行慢（内核指标）分别下钻。

## 10.5 日志规范

- 统一 `log/slog` 结构化日志，`trace_id` 贯穿 SQL→命令；
- Lua 脚本业务性返回（stale/duplicate）不记 error 级（属正常路径），仅计数 + debug；
- 网关为独立进程，日志输出由启动参数配置；`WithLogger` Option 供测试与带外工具注入 Handler。
