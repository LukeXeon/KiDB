# KiDB：Redis 集群 SQL 查询层 · 详细设计

> 项目代号：**KiDB**（开源项目）
> 版本：**v5.0**（全面革新版）
> 定位：以 **MySQL 协议网关（server 单形态）** 交付的分布式 SQL 缓存查询层，基于可替换的 Redis 集群客户端抽象（`Client` 接口），SQL 引擎采用 go-mysql-server，DDL 解析直接依赖 TiDB `pkg/parser`。

## v5.0 革新点

1. **落地为代码仓库**：文档与 `/kidb` 仓库的 Go 包一一对应，文档即接口契约，不再是伪码骨架；
2. **SQL 服务器升格为核心**（[02](02-SQL服务器.md)）：协议层、前置分类器、双解析器分工、会话、版本绑定的 plan cache、DDL 作业化；
3. **TiDB 对齐工程化**（[13](13-TiDB复用清单.md)）：叙述方式改为**推导式**——每个机制章以 "TiDB 参照 → Redis 约束 → KiDB 设计" 三段开篇，KiDB 不是另起炉灶的设计，而是 TiDB 架构经 Redis 约束的翻译；能直接依赖的走 go.mod（`pkg/parser` 独立模块，零修改零 fork），不能依赖的按"设计移植清单"照着重写，整层搬不动的给出依赖链尸检；
4. **元数据引入 schema lease 纪律**（[06](06-元数据与Schema演进.md)），plan cache 随 schema 版本失效——对齐 TiDB `domain`/`plan_cache`；
5. **契约增补错误分类与退避矩阵**（[09](09-后端契约与适配器.md) §9.6）——对齐 client-go `Backoffer`；
6. **部署形态收敛为网关单形态**（v4.3 决策延续，[11](11-部署与运维.md) §11.2）；
7. 三方库策略不变：**能用库的用库**（go-mysql-server / ARC / singleflight / conc / msgp …），能搬 TiDB 的搬 TiDB，都不存在才自研薄层。

## 一页纸概述

**为什么做这个**：缓存使用里最累的不是 Redis 本身，而是围绕它的设计劳动——key 命名规范、二级索引维护、cache-aside 的回填/失效时序。KiDB 的目标是让这些劳动消失：业务方只需要会 SQL，连上的是一个"长得像 MySQL"的缓存。

KiDB 把 Redis Cluster 包装成一个支持单表 SQL 的缓存查询层，以 MySQL 协议网关交付：

- **数据模型**：行存 Hash（`d:{table}:{pk}`），二级索引存按 slot 内聚的 ZSet 桶，过期信息存 `exp:{table}:{stag}` 登记册，全部通过 hash tag 保证同行数据同 slot（[03](03-数据模型与编码.md)）；
- **SQL 面**：DDL 走 TiDB `pkg/parser`（KiDB 扩展经 COMMENT 载体），DML 走 go-mysql-server 引擎，前置分类器按首关键字路由（[02](02-SQL服务器.md)）；
- **写路径**：单 slot Lua 原子完成"读旧行 → 撤旧索引 → 写新行 → 建新索引 → 登记过期"（[05](05-写入路径.md)）；
- **读路径**：谓词翻译为桶命令 → scatter-gather（Request 对象）→ 批量回表 → 谓词校验，流式输出，全链路有界；**零 SCAN 依赖**（[04](04-查询路径.md)）；
- **自治**：桶在线分裂合并、热 key 四层防御、过期分布式清扫、Controller 锁选举 + watchdog（[08](08-自治治理与热Key.md)）；
- **正确性纪律**：结果必须精确（回表校验兜底一切异步路径），统计可以近似（HLL/采样，仅用于决策）；
- **可移植**：内核零依赖具体 Redis 客户端；适配器有一致性测试套件把关（[09](09-后端契约与适配器.md)、[12](12-测试方案.md)）。

## 适用边界（速判）

本项目的初衷：**把缓存设计的门槛降到零**——不用设计 key 命名规范、不用手写二级索引、不用处理 cache-aside 的时序 bug，一切用熟悉的 SQL 做结构化查询。这个价值与数据规模无关：小业务的缓存同样值得被正确、省心地管理。

✅ 适合：任何需要"按主键以外字段查询缓存"的场景。数据量小、查询模式固定时，自治机制（分裂/合并、L4 副本、Sweeper 提速）自然休眠，不占任何成本——它们是为"长大"的那一天预置的，而不是入场费。

❌ 真正的边界（全是能力与语义层面，与规模无关）：跨 slot 多行事务；大表任意 JOIN；强一致读；对 ~0.3ms→~1ms+网关一跳的延迟税极端敏感的超热路径；不提供 EVAL 的 Redis 平台。
